# PRD: OpenSQL AI 문서관리 플랫폼

## 목표
문서를 업로드하면 DB 계층의 트리거만으로 임베딩 생성·벡터 인덱싱이 자동 갱신되어, 노드 장애 중에도 끊기지 않는 의미기반 문서 검색을 제공한다.

## 사용자
- 사내 문서(규정·매뉴얼·보고서)를 키워드가 아닌 의미로 검색하고 싶은 조직 구성원
- MCP를 통해 사내 문서를 직접 검색·활용하는 AI 에이전트 (Claude 등)
- (대회 관점) openSQL의 고가용성·pgvector 활용도를 평가하는 심사위원

## 핵심 기능
1. **문서 업로드 → 자동 임베딩 파이프라인**: PDF/DOCX/TXT/MD 업로드 시 DB 트리거가 임베딩 작업을 생성하고, 워커가 청킹·임베딩·벡터 저장까지 자동 처리. 업로드 코드에는 임베딩 호출이 없다.
2. **하이브리드 시맨틱 검색**: 태그·문서 유형·권한 같은 정형 필터와 pgvector 코사인 유사도를 단일 SQL로 결합한 검색.
3. **버전 관리와 자동 재임베딩**: 문서 수정 시 버전 이력이 쌓이고, 변경 감지 트리거가 재임베딩을 자동 기동. 재임베딩 완료 전까지는 이전 벡터로 검색이 계속된다(검색 공백 없음).
4. **페일오버 자동 복구**: openSQL Primary 노드 장애 시 OpenProxy가 새 Primary를 추적해 재연결하고, API·워커는 끊긴 연결을 재수립한다. 작업 큐가 DB에 복제되어 있어 미처리 임베딩 작업도 유실 없이 재개된다. **사용자는 장애 사실을 인지하지 않는다** — 업로드와 검색이 계속 동작한다.

   > 정확한 표현은 "무중단"이 아니라 **"짧은 중단 후 자동 복구"**다. OpenSQL의 Patroni 설정 기준(`ttl=30s`) 장애 감지부터 승격까지 수십 초가 걸리며, 그 구간의 요청은 실패한다. 문서·데모에서 과장하지 않는다.
5. **MCP 검색 툴**: AI 에이전트가 `search_documents` 등 툴로 플랫폼의 문서를 의미 검색.

## MVP 제외 사항
- 실제 인증/인가 시스템 — `X-User-Id` 헤더 기반 데모 사용자 + `visibility`/`owner_id` SQL 필터로 "권한이 벡터 검색과 결합됨"만 시연
- HWP/HWPX 파싱 — 파서 품질 리스크가 큼. 4종(PDF/DOCX/TXT/MD) 완성 후 여유 시에만 검토
- SSE/웹소켓 실시간 알림 — 프론트 폴링(2초)으로 대체
- 임베딩 배칭·캐싱·폴백 체인 — 데모 규모에서 불필요한 최적화
- 다국어 UI, 모바일 대응
