# PRD: OpenSQL AI 문서관리 플랫폼

## 목표

**AI에게 주는 근거가 어느 시점에도 하나의 일관된 버전이고, 최신 버전으로 수렴함을 데이터베이스가 보장하는 문서 저장소를 만든다.**

문서를 업로드하거나 수정하면 DB 계층의 트리거만으로 임베딩 생성·벡터 인덱싱이 갱신되고, 노드 장애 후에도 스스로 복구된다. 애플리케이션 코드에는 임베딩 파이프라인을 조율하는 부분이 없다.

> **보장 범위를 정확히 쓴다 (ADR-015).** "항상 최신"이 아니다. 재임베딩 중에는 이전 버전 청크로 검색되고, 워커 폴링 주기와 임베딩 소요만큼 반영이 늦다. 우리가 보장하는 것은 **버전 일관성**(활성 청크가 여러 버전으로 섞이지 않음)과 **최신으로의 수렴**이며, 어긋난 구간은 정합성 검증 쿼리로 **관측할 수 있다**. 이것이 "항상 최신"보다 강한 주장이다 — 증명할 수 있기 때문이다.

## 사용자
- 사내 문서(규정·매뉴얼·보고서)를 키워드가 아닌 의미로 검색하고 싶은 조직 구성원
- MCP를 통해 사내 문서를 근거로 활용하는 AI 에이전트 (Claude 등)
- (대회 관점) OpenSQL의 고가용성·pgvector 활용도를 평가하는 심사위원

## 핵심 기능

1. **문서 업로드 → 자동 임베딩 파이프라인**: PDF/DOCX/TXT/MD 업로드 시 **파일에서 텍스트를 추출해 저장**하고, DB 트리거가 임베딩 작업을 생성한다. 워커가 청킹·임베딩·벡터 저장까지 자동 처리한다. 업로드 코드에는 임베딩 호출이 없다. **원본 파일은 보관하지 않는다** — 저장되는 것은 추출 텍스트다.

2. **하이브리드 시맨틱 검색**: 태그·문서 유형·권한 같은 정형 필터와 pgvector 코사인 유사도를 단일 SQL로 결합한 검색.

3. **텍스트 버전 관리와 자동 재임베딩**: 문서를 수정하면 텍스트 버전 이력이 쌓이고, 변경 감지 트리거가 재임베딩을 자동 기동한다. **플랫폼 안에서 직접 편집할 수 있다** — 편집 대상은 **추출 텍스트의 새 논리 버전**이며 원본 파일이 아니다(ADR-017). 재임베딩 완료 전까지는 이전 벡터로 검색이 계속된다(검색 공백 없음).

4. **문서 관계 저장과 그래프 검색**: 임베딩 완료 트리거가 청크 이웃에서 `overlaps`·`related`
   관계를 만들고, 검색은 벡터 진입점에서 열람 가능한 관계와 직전 텍스트 버전·위키링크를 깊이 2까지
   확장한다(ADR-027·029·030). 관련 문서와 태그 추천도 같은 저장 관계를 사용한다. 볼 수 없는 문서는
   결과뿐 아니라 순회 경로와 집계에서도 제외한다.

   > 유사도 점수는 **비대칭 지표**라 중복 판정에 쓰지 않는다. "중복입니다"가 아니라 "내용이 유사한 문서가 있습니다"로 표시하고, 판단은 사람이 한다. 완전히 동일한 텍스트는 `content_hash` 일치로 따로 확정한다.

5. **페일오버 자동 복구**: OpenSQL Primary 노드 장애 시 OpenProxy가 새 Primary를 추적해 재연결하고, API·워커는 끊긴 연결을 재수립한다. 작업 큐가 DB에 복제되어 있어 미처리 임베딩 작업도 유실 없이 재개된다. **사용자는 장애 사실을 인지하지 않는다** — 업로드와 검색이 계속 동작한다.

   > 정확한 표현은 "무중단"이 아니라 **"짧은 중단 후 자동 복구"**다. OpenSQL의 Patroni 설정 기준(`ttl=30s`) 장애 감지부터 승격까지 수십 초가 걸리며, 그 구간의 요청은 실패한다. 문서·데모에서 과장하지 않는다.

6. **MCP 근거 게이트웨이**: AI 에이전트에 사내 문서의 근거를 공급한다. `search_documents` 등의 툴로 의미 검색 결과를 발췌·출처·기준 버전과 함께 반환한다.

   > **답변 생성은 플랫폼이 하지 않는다** (ADR-015). 생성 LLM을 탑재하지 않으며, 답변은 MCP 클라이언트가 만든다. "AI가 사내 문서만을 근거로 답하게 한다"고 쓰지 않는 이유는, 클라이언트가 자기 지식으로 답하는 것을 우리가 막을 수단이 없기 때문이다. 우리의 책임은 **근거 공급**까지다.

7. **문서 정리와 탐색 화면**: 열람 범위 안에서 고아 문서, 동일 텍스트, 여러 대목에서 만나는
   문서, 미분류 문서, 깨진 위키링크를 진단한다. 태그 기반 주제 덩어리와 덩어리 사이 연결을
   그래프로 보여주며, `[[제목]]` 링크와 백링크로 문서를 오간다. 순위 기반 관계에서 정의할 수
   없었던 “빠진 연결” 진단은 만들지 않았다.

## 검토 후 미채택

- **키워드 + 벡터 RRF 결합** (ADR-016): `to_tsvector('simple')` 원안은 한국어 조사 때문에
  0건을 반환해 `pg_trgm`으로 바꿔 측정했다. 실 BGE-M3 63문서·299청크의 10질의 비교에서
  `OpenProxy`·`OpenSQL`·`태그 추천`의 벡터 상위 결과를 낮췄고 K 조정으로도 개선되지 않아 제품
  검색에는 채택하지 않았다. 검색은 벡터 진입점과 그래프 확장을 유지한다.

## MVP 제외 사항
- 실무 ECM의 전체 인증·인가 — 세션 로그인과 관리자 발급 계정은 범위에 들어왔지만 문서 단위 `public`/`private`만 지원하는 최소형이다. 그룹·공간·권한 상속·디렉터리 연동은 여전히 MVP 밖이다 (ADR-028)
- **원본 파일 보관·다운로드** — 저장하는 것은 추출 텍스트뿐이다. 업로드한 PDF/DOCX 자체를 다시 받을 수 없다 (ADR-017)
- 플랫폼 내 답변 생성 LLM — MCP 클라이언트에 위임 (ADR-015)
- HWP/HWPX 파싱 — 파서 품질 리스크가 큼. 4종(PDF/DOCX/TXT/MD) 완성 후 여유 시에만 검토
- SSE/웹소켓 실시간 알림 — 프론트 폴링(2초)으로 대체
- 임베딩 배칭·캐싱·폴백 체인 — 데모 규모에서 불필요한 최적화
- 다국어 UI, 모바일 대응
