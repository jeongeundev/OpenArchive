# Project Context

## 프로젝트 개요

프로젝트명: **OpenSQL 기반 AI 문서관리 플랫폼**

오픈소스 개발자 대회 기업 지정과제

> **고가용성 DBMS인 OpenSQL을 기반으로 문서 임베딩, 벡터 인덱싱, 의미 기반 검색을 자동화한 AI 문서관리 플랫폼을 구축한다.**

사용자가 문서를 업로드하면 AI가 문서를 이해하고, 임베딩 생성부터 벡터 저장, 의미 기반 검색까지 자동으로 수행되는 플랫폼을 구축한다.

---

# 기업이 제시한 OpenSQL의 핵심 가치

OpenSQL은 PostgreSQL 기반의 고가용성 DBMS이며 다음 특징을 가진다.

## 1. 고가용성(High Availability)

- 노드 간 클러스터 상태 공유
- 장애 자동 감지
- 자동 Failover
- 새로운 Primary 자동 선출(Promotion)

DB 장애가 발생하더라도 서비스를 지속할 수 있도록 설계되어 있다.

---

## 2. 내장 벡터 검색

pgvector 등 다양한 Extension을 제공하여

- 벡터 저장
- 벡터 인덱싱
- 의미 기반 검색

을 별도의 Vector DB 없이 OpenSQL 내부에서 처리할 수 있다.

---

# 기업이 해결하려는 문제

기업이 OpenSQL을 사용하는 이유는 다음 두 가지 문제를 해결하기 위함이다.

## 1. 고가용성 부족

기존 구조에서는 DB 장애가 서비스 전체 장애로 이어질 수 있다.

OpenSQL은 자동 Failover를 통해 서비스 중단 없이 운영되는 플랫폼을 구축하는 것을 목표로 한다.

---

## 2. 원본 데이터와 벡터 데이터의 정합성

문서가 변경될 때마다

- 임베딩 생성
- 벡터 인덱스 갱신

을 수동으로 수행하거나 별도 파이프라인으로 처리하면

원본 데이터와 벡터 데이터가 서로 다른 상태가 될 수 있다.

OpenSQL에서는 문서 입력 및 변경 이벤트를 기반으로

- 자동 임베딩
- 자동 벡터 갱신

이 이루어져 원본과 벡터 데이터의 정합성을 유지하는 것이 핵심이다.

---

# 프로젝트 목표

다음 과정을 하나의 자동화된 파이프라인으로 구축한다.

```
문서 업로드

↓

문서 저장

↓

자동 임베딩 생성

↓

자동 벡터 동기화

↓

의미 기반 검색

↓

MCP 검색 API (선택)
```

---

# 핵심 구현 목표

## 1. OpenSQL의 고가용성 활용

- Failover 이후에도 서비스 지속
- 플랫폼이 새로운 Primary에 정상적으로 복구
- 사용자는 장애를 인지하지 않고 서비스를 이용

---

## 2. DB 계층 중심 자동화

문서 생성 및 변경 이벤트 발생 시

DB 계층을 중심으로

- 임베딩 작업 생성
- 벡터 갱신
- 원본과 벡터 데이터 정합성 유지

가 자동으로 수행되는 구조를 구현한다.

---

## 3. 정형 데이터 + 벡터 데이터 결합

OpenSQL을 단순한 Vector DB처럼 사용하는 것이 아니라

### 정형 데이터

- 문서
- 메타데이터
- 버전
- 권한
- 태그

↓

RDBMS

### 비정형 데이터

- 문서 본문
- 임베딩 벡터

↓

pgvector

를 함께 활용하는 하이브리드 구조를 구축한다.

---

# 프로젝트의 핵심 가치

이 프로젝트는 단순한 RAG 시스템을 만드는 것이 아니다.

OpenSQL이 제공하는

- 고가용성
- 정형 데이터 관리
- 벡터 검색

을 하나의 플랫폼으로 통합하여

문서 변경 이후에도 원본과 벡터 데이터의 정합성을 유지하는 AI 문서관리 플랫폼을 구축하는 것이 목적이다.

- **API 전용 모델(Closed API)은 출품작 기능으로 사용 불가** (제9조 ②1.다, [별표2])

    `OpenAIProvider`는 **구현하지 않는다** (ADR-003)
- ✅ **예외 — MCP는 "적극 허용하며 권장"** ([별표2])
  > "MCP(Model Context Protocol), AI 에이전트 프레임워크 등 'AI 모델과의 연동 및 개발 보조 생태계' 자체를 활성화하기 위한 라이브러리, 커넥터, 플러그인 형태의 소프트웨어 개발 및 출품은 적극 허용하며 권장함"
  - → **MCP 서버(ADR-008)는 규정이 권장하는 형태다. 범위를 축소하더라도 빼지 않는다.**
