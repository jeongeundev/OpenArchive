## 정체성: 어디까지가 코어인가

OpenArchive의 코어는 **Tmax OpenSQL 위에서 도는 문서 지식 플랫폼**이다.
저장·임베딩 파이프라인 조율(트리거)·원본-벡터 정합성·하이브리드 검색·관계 그래프가 전부
DB 계층에 있고, 애플리케이션 코드에는 파이프라인을 조율하는 부분이 없다.

- **OpenSQL이 기반이다.** 모든 상태가 한 DB에 있어 OpenSQL HA 3노드(OpenProxy VIP 단일 엔드포인트)의
  failover와 Barman 백업이 곧 파이프라인 전체의 복구다 — 장애·복원 실측도 거기서 했다 (PRD 「정의와
  가치」 절, ADR-020·053). 코어가 쓰는 것은 PostgreSQL 17 + pgvector의 표준 기능뿐이라 일상 개발과
  전체 테스트는 공개 `pgvector/pgvector:pg17` 이미지에서도 돌고(ADR-026), 자기 PostgreSQL에 올려 써 볼
  수도 있다 — 이 이식성은 채택을 돕는 부가 성질이다.
- **비슷한 오픈소스와의 차이.** Paperless-ngx는 파이프라인 조율을 앱(Celery)이 맡고, Onyx(구
  Danswer)는 벡터를 별도 엔진(Vespa)에 둔다 — 원본과 파생 데이터의 정합성이 앱 코드의 책임이 된다.
  OpenArchive는 조율과 벡터가 **같은 DB 트랜잭션 경계 안**에 있어, 정합성을 앱이 아니라 DB가
  보장하고 어긋난 구간을 쿼리로 관측할 수 있다 (PRD 「정의와 가치」 절).

### 다섯 구분으로 본 현재 구조

시스템을 설명할 때 다음 다섯 구분을 쓴다. **설명용 개념 모델이며 공식 용어가 아니다**
(ADR-031 결정 2) — 커밋 스코프·디렉토리·"DB 계층" 같은 기존 어휘를 대체하지 않는다.

| 구분 | 현재 구현 | 상태 |
|---|---|---|
| **Ingestion** (수집) | `POST /api/documents`(파일 업로드)와 `POST /api/documents/text`(JSON 텍스트) → `services/documents.py`의 두 입력 어댑터 → 공통 INSERT 헬퍼. MCP `create_document`와 CLI `import`도 같은 services 진입점을 쓴다 | HTTP 진입점 2개 + MCP·CLI, 파일 11종(이미지·스캔 PDF는 워커가 OCR) + 직접 텍스트 2종. Web UI의 다중 파일·ZIP 대량 투입도 단건 업로드와 같은 파생 계약을 사용 (ADR-033·035·036) |
| **Processing** (변환·임베딩) | DB 트리거(잡 생성·코얼레싱) + 워커(청킹·임베딩) + edge 트리거(관계 생성) | 견고 — 조율이 전부 DB 안에 있다 |
| **Storage** (저장·정합성) | 문서·텍스트 버전·청크·잡 큐·관계·원본 판 테이블과 인증·열람 부여 테이블, 제약·CASCADE·`vector(1024)` 타입, 정합성 관측 쿼리 | 코어 계약(ADR-015)의 자리 |
| **Retrieval** (검색·관계) | 단일 SQL 검색(정형+벡터+그래프) · 저장 edge · 위키링크 · 진단·클러스터 | 전 경로가 같은 열람 술어를 공유 (ADR-027) |
| **Interface** (소비·공급) | Web UI · REST API · MCP(로컬 stdio) · 운영자 CLI — 같은 services 계층을 사용하는 대등한 인터페이스 (ADR-031 결정 3) | REST 위임 API 토큰과 MCP `create_document`로 비대화형 공급 가능 (ADR-034·036). 원격 MCP·사용자 CLI는 채택됨 → PRD §5 C4 (ADR-056·057). 커넥터는 다음 확장 |

## 확장점과 후보

원칙: 아래 항목 대부분은 코어를 바꾸지 않는다. 수집기는 `documents`에 INSERT하는 클라이언트일
뿐이고(임베딩 잡은 트리거가 만든다), 파서·임베딩 프로바이더는 인터페이스 뒤에 있다. 그래서
각 항목이 독립적인 기여 단위가 된다. 항목의 채택 여부와 순서는 아래 「단계적 발전 경로」에
비추어 판단한다 (ADR-031 결정 4).

### 파서 (`backend/openarchive/services/parsing.py`)

| 그림뿐인 오피스 문서 OCR | 채택·진행 (#177) | 텍스트가 없고 그림만 있는 오피스 문서를 거부하지 않고 그림 속 글자를 인식한다 → PRD §5 C1 |

### 수집 커넥터 (= `documents` INSERT 클라이언트)

1차 범위의 대량 투입 최소형(#54)은 Web UI의 다중 파일 선택과 브라우저 ZIP 해제로 구현됐다
(ADR-033). 서버에는 배치 API를 추가하지 않고 기존 단건 업로드를 재사용한다. 그 다음:

| IMAP(이메일 수집) | 장기 | |
| 외부 DB 커넥터 | 장기 | 원본 PK·수정 시각·내용 해시 기반 증분 동기화. 삭제는 실삭제 대신 보관 전환이 안전하다. 동기화 문서와 OpenArchive 안에서의 텍스트 편집(ADR-017)의 충돌은 채택 전에 source-of-truth 규칙을 ADR로 정해야 한다 |

### 검토 워크플로

- **inbox 태그 최소형** (2차 후보): 업로드 시 일괄 태그의 연장 — 새 문서에 검토용 태그를 붙이고,
  검토 후 태그를 떼는 흐름. 상태 기계를 새로 만들지 않고 기존 태그·필터(ADR-024)를 재사용한다.
  승인 플로·상태 컬럼은 이 최소형으로 부족하다는 것이 확인된 뒤에만 검토한다.

### 원본 파일 보관

- **판 보관 정책** (2차 후보): 원본 판은 교체할수록 누적되고(ADR-046) 개수·기간 제한과 이전 판 정리가 없다.
  DB 크기가 실제로 문제가 되는 규모를 확인한 뒤 정책을 정한다 — 정리해도 텍스트 버전과의 연결(`text_version`)은
  남겨야 한다.
- **원본 미리보기**: 채택됨 → PRD §5 C1 (ADR-058, #190).

### 문서 관리 기준선

- **폴더 트리와 열람 범위 상속**: 채택됨 → PRD §5 C3·§6 (ADR-054, #187).
- **감사 로그**: 채택됨 → PRD §5 C2 (ADR-055, #186).
- **텍스트 버전 비교**: 채택됨 → PRD §5 C1 (ADR-037, #190).
- **사용자 CLI**(REST 클라이언트): 채택됨 → PRD §5 C4 (ADR-057, #189).

### 임베딩 프로바이더 (`bge-m3` / `fake` 추상화 존재)

- open-weight 모델 추가, 리랭커 (장기). 벡터 컬럼은 `vector(1024)` 고정 — 프로바이더가 바뀌어도
  차원은 바꾸지 않는다 (CLAUDE.md 규칙).

### 검색

- **한국어 형태소 분석기 기반 키워드 랭킹** (2차 후보): trigram은 순위를 만들지 못해 RRF를
  접었다 (ADR-016). 형태소 분석기가 생기면 키워드+벡터 융합을 다시 본다 — PRD가 예약해 둔 항목.

### MCP · 이벤트

- **현재**: MCP는 읽기 3개와 쓰기 `create_document` 1개를 제공한다. 쓰기는 `MCP_USER_ID`가
  없으면 거부하고 기존 텍스트 진입점을 재사용한다 (ADR-025·036).
- **원격 transport**: 채택됨 → PRD §5 C4 (Streamable HTTP + Bearer API 토큰, ADR-056, #188).
- update/delete 도구 (후보): 수정의 동시성과 삭제 승인을 각각 결정한 뒤 추가한다.
- 이벤트 웹훅 (장기): "임베딩 완료" 등 이벤트 발행 — 서드파티 통합의 진입로.

### 권한

- **주체(사용자·그룹·공유) + 부여 모델**: 채택됨 → PRD §6 (ADR-044, #97 a~c 구현).
- **폴더 열람 범위 상속**: 채택됨 → PRD §6 (ADR-054, 결정·미구현 #187).
- **RLS 강제** (후보): 강제를 DB(RLS)에서 할지는 실OpenSQL 스파이크(#98) 뒤 별도 ADR. 열람 범위
  술어가 한 곳(`visibility.py`)에 있어 교체 지점도 한 곳이다.
- 쓰기 권한 부여, SSO·사내 디렉터리 연동, 서비스 주체 (장기). 태그 단위 부여와 관리자 열람은 하지
  않는다(아래 「하지 않는 것」).

## 단계적 발전 경로

확장점 후보를 개별로 저울질하지 않고 이 경로에 비추어 정한다 (ADR-031 결정 4). 각 단계는
앞 단계의 증명 위에 서고, 착수 전 필요한 결정은 그 시점의 ADR/spec으로 확정한다 — 이 표는
목표와 착수 조건까지만 적는다.

| 단계 | 목표 | 착수 전 필요한 결정 |
|---|---|---|
| **0. 신뢰 가능한 파이프라인** (증명됨) | 원본-벡터 정합성·장애 복구·하이브리드 검색을 실측으로 증명한다 | — (OpenSQL HA 3노드 failover·Barman 복원까지 실측, ADR-020·053) |
| **1. 프로그래매틱 플랫폼** (현재 — M11로 HTTP 공급·위임 토큰·MCP 쓰기 구현, 첫 커넥터가 남음) | **프로그래매틱 인제스천을 1급 경로로 증명한다.** 성공 기준: 외부 프로세스가 `backend` 패키지를 import하지 않고 **HTTP만으로** 문서를 공급하며, 파이프라인(임베딩·관계·링크)이 웹 업로드와 동일하게 동작한다 | 텍스트 직접 생성 API 의미론·CORS 미도입은 **ADR-035**, 위임 토큰 인증과 `X-User-Id` 제거의 정합은 **ADR-034**, MCP 쓰기는 **ADR-036**으로 확정. 남은 결정: 첫 커넥터 선정 |
| **2. 외부 소스 연결** | 커넥터를 늘리고 증분 동기화를 지원한다 | source-of-truth 규칙 ADR(동기화 문서 vs OpenArchive 안에서의 텍스트 편집 ADR-017 — 위 외부 DB 커넥터 메모) · 출처(provenance) 스키마 |
| **3. 지식 큐레이션 최소형** | 이미 있는 프리미티브를 워크플로로 승격한다 — 중복 판정(`content_hash`·`overlaps`)→병합, inbox 태그 검토, 버전 해소. ADR-029 노선대로 벡터+SQL로, 생성 LLM 없이. 군집(#85, ADR-042)은 조회 시점 Louvain으로 들어갔다. 키워드 라벨은 미착수 | `UI_GUIDE.md`의 "자동 병합하지 않는다" 제동 재검토 |
| **4. Knowledge Base / Living LLM Wiki** | 문서 소스를 연결하면 선별·정리·관계화된 지식이 지속 갱신되는 위키에 도달한다 | 답변 생성은 ADR-043이 옵션 레이어로 내장하고 인용에 기준 버전을 붙였다(구현 #96 a·b, 모델 `qwen3:8b`, 한국어 품질 확정은 #96 c). 남은 결정: 정리된 지식 자체의 생성·유지, LLM 엔티티 그래프(온톨로지) — 로컬 open-weight 모델의 품질·문서당 비용·정규화가 착수 조건 |

## 배포와 설치 — open-webui 형태로

> 2026-08-27 결정, #95로 완료. `pipx install openarchive-server[local]` → `openarchive init --dsn …` →
> `openarchive serve`(API·워커·웹을 한 명령으로)가 PyPI `openarchive-server` 0.1.0(2026-10-01, 태그
> `v0.1.0`)으로 동작한다. 마이그레이션은 패키지 안에 있고, `init`이 첫 관리자 계정까지 만든다(ADR-039·041).

**남은 것** — #100 릴리스 워크플로: Trusted Publishing(토큰 없는 PyPI 게시)과 앱 컨테이너 이미지
(`backend/Dockerfile`)의 ghcr 게시(amd64·arm64). 그 전까지 README는 저장소에서 `docker build`로
안내한다. 이미지 실측은 arm64·로컬 pgvector뿐이다(같은 패키지의 실 OpenSQL 기동은 pip 설치로 확인).

이미지에 **DB는 넣지 않는다** — 앱은 조직의 OpenSQL에 붙는 클라이언트다. 첫 가입자가 관리자가 되는
방식도 두지 않는다 — 자체 가입이 없는 것은 결정이다 (ADR-028).

**여기서 하지 않는 것** — sqlite 같은 무설정 DB 기본값. 트리거 아웃박스가 제품이라 DB를
대체하면 제품이 사라진다. `init`이 DSN 한 줄을 받는 것이 최소형이다. 플러그인 런타임도 두지
않는다 — 확장은 HTTP·MCP로 **밖에** 둔다(위 「확장점과 후보」).

## 하지 않는 것

> 제품 차원의 전체 목록은 **PRD 「하지 않는 것」 절이 정본**이다 (ADR-032). 아래는
> 확장 후보를 저울질할 때 직접 걸리는 항목만 다시 적은 것이다.

- **범용 DB 마이그레이션** (테이블·제약·프로시저 이전) — 별도 제품의 영역이다. 우리가 다루는
  것은 문서성 데이터의 수집뿐이다.
- **근거를 만드는 파이프라인 안의 LLM** — 청킹·임베딩·관계는 결정론이다. 답변 생성은 옵션
  레이어이며 기본 꺼짐이다 (ADR-043, ADR-015 결정 3 개정). 에이전트 프레임워크·라우터는 MCP
  클라이언트의 층이라 들이지 않는다.
- **"항상 최신" 보장** — 보장 범위는 버전 일관성 + 최신 수렴이다 (ADR-015).
- **휴지통** — 삭제는 영구이고, 잘못 지운 문서는 관리자가 백업에서 시점 복원(PITR)한다 (ADR-053).
- **ECM 전체** — 폴더와 변경 감사 기록은 하지만, 열람 기록·보존 정책(보존 기간·자동 폐기)·기록물
  이관·전자결재·법적 보존(legal hold)은 하지 않는다 (PRD 「하지 않는 것」).
- **태그 단위 열람 부여** — 태그는 분류이지 권한 경계가 아니다. 부여 대상은 문서와 폴더뿐이다
  (ADR-044 결정 2, ADR-054).

## 운영 메모

실 DB 환경은 OpenSQL HA 3노드(node1~3, Patroni·etcd·OpenProxy VIP)와 Barman 백업 전용 node4다 —
구성·라이선스·재구성 절차는 `docs/SETUP_OPENSQL.md`가 정본이다. 일상 개발과 전체 테스트는 공개
`pgvector/pgvector:pg17` 컨테이너에서 하고(ADR-026), OpenSQL 고유 동작(OpenProxy·failover·백업 복원)은
이 환경에서 실측한다.
