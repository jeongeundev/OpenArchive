# UI 디자인 가이드

## 디자인 원칙
1. 도구처럼 보여야 한다. 마케팅 페이지가 아니라 매일 쓰는 문서관리 대시보드.
2. 데이터가 주인공이다. 문서 목록·임베딩 상태·검색 결과가 장식 없이 즉시 읽혀야 한다.
3. **사용자 화면은 인프라를 드러내지 않는다.** 사용자가 확인해야 하는 것은 "장애가 났다"는 사실이 아니라 **"업로드와 검색이 오류 없이 계속 동작한다"**는 결과다. 접속 DB 노드, 페일오버 발생 여부 같은 운영 정보는 사용자 화면에 넣지 않는다.
4. 운영·데모용 관측은 **별도 채널**로 분리한다 — 관리자 전용 상태 패널, `GET /api/system/status`, 워커·API 터미널 로그. 복구 증거는 여기서 보여준다.

> **원칙 3의 배경**: 고가용성의 가치 명제는 "사용자가 장애를 인지하지 않는다"이다(`PROJECT_CONTEXT.md` 핵심 구현 목표 1). 사용자 화면에 노드 IP를 띄우는 것은 그 명제와 모순된다. 데모에서는 사용자 화면(정상 동작)과 관측 채널(장애·복구 증거)을 **나란히** 보여주는 것이 더 강한 증명이다.

## 화면 구성

### 사용자 화면 (8화면)

**모든 문서 화면은 로그인을 요구한다** — 익명은 아무 문서도 보지 못하며 읽기 API도 401을 준다 (ADR-028). 익명에게 열린 것은 `/login`뿐이다.

> 이 요구는 **`RequireAuth`(layout 전역)가 한 자리에서** 처리한다. 개별 화면에 로그인 확인·익명 안내를 또 두지 않는다 — 실앱에서 도달하지 않는 분기가 되고, `RequireAuth` 없이 마운트하는 컴포넌트 테스트만 그 죽은 경로를 지난다.

1. `/` — 문서 목록 테이블 + 업로드 드롭존. 업로드에서 「조직 공개 / 제한」을 고르고, 제한이면 사용자·그룹을 부여 대상으로 선택한다. 각 행에 임베딩 상태 배지 — 인식 중·실패 문서는 텍스트 인식 배지(2초 폴링 갱신). 업로드 아래, 단계별 수와 목록 위에 찾기 컨트롤을 「제목 검색」·「문서 유형」·「태그」·「정렬」 순으로 둔다. 넓은 화면은 4열, 좁은 화면은 세로로 배치한다. 제목 검색은 입력 후 300ms에 반영하며 유형은 「전체」와 대문자 유형, 태그는 「전체」와 열람 가능한 문서의 태그 목록을 표시한다. 정렬은 「최근 수정순」이 기본이고 「제목순」을 선택할 수 있다. 목록 위의 "문서 N건 · 단계별 수"(`/api/documents/progress`)는 열람 범위 전체를 세고, 페이지는 찾기 조건의 건수(`/api/documents/count`)로 50건씩 이전/다음으로 넘긴다. 조건을 바꾸면 첫 페이지로 돌아간다. 볼 수 있는 문서가 있지만 제목·유형·태그 조건에 맞는 결과가 없으면 「조건에 맞는 문서가 없습니다.」를 표시한다. 열람 범위 전체에 문서가 없으면 첫 사용 안내로 업로드와 `openarchive demo --user <로그인 계정>`을 안내한다 (#95-d)
2. `/documents/[id]` — 메타데이터, **열람 범위** 패널(소유자에게만 표시), **원본 파일**(판 목록·내려받기·교체·다시 추출), **텍스트 버전 이력**(각 버전의 본문 보기·되돌리기 — 과거 버전 본문은 `[[제목]]`을 링크로 바꾸지 않고 그때의 문서 텍스트 그대로 보인다. 링크 해석 결과(`document_links`)는 **현재 텍스트 버전** 것만 있으므로, 과거 본문에 걸면 그때 있던 링크가 깨진 링크로 그려지거나 지금의 대상으로 이어진다 — #79 ⑤), 청크 수·기준 버전 요약, **문서 텍스트 편집**, 관련 문서, 태그 추천
3. `/search` — 질의 입력 + 태그/유형 필터 + 결과 목록(유사도 점수, 매칭 청크 발췌, **문서 상세 링크**). "실행된 SQL 보기" 토글. 로그인 사용자에게는 검색 뒤 결과 위에 **근거 기반 답변 패널**(아래)
4. `/clusters` — 관계 그래프의 군집으로 묶은 덩어리와 덩어리 사이 연결을 SVG로 보여준다. 선의 굵기는 **덩어리 사이를 잇는 문서쌍 수**다. 원 크기·선 굵기는 화면 안 **최소~최대 범위**에서의 상대 위치로 그린다 — 최대값만 기준으로 삼으면 덩어리가 균질할 때 모두 같은 크기로 보인다(#89 ②). 이름은 **군집에 집중된 태그**(안−밖 빈도 차가 양수인 것 중 최대)이고, 그런 태그가 없으면 연결이 많은 문서 제목을 쓰며, 겹치면 번호를 붙인다 (ADR-042 개정)
5. `/diagnostics` — 내가 볼 수 있는 문서의 고아·중복 후보·미분류. **운영 화면이 아니다** — 집계 범위가 열람 범위와 같아 사람마다 다른 값이 나온다
6. `/login` — 사용자명·비밀번호. 자체 가입은 없고 계정은 관리자가 발급한다
7. `/settings` — **계정 설정.** 헤더의 사용자명으로 들어간다. API 토큰 발급·목록·폐기와 자기 비밀번호 변경. 모든 동작이 자기 자신에게만 미치므로 관리 화면이 아니다 (ADR-040)
   - 원문 토큰은 발급 직후 한 번만 보여주고 목록에는 남기지 않는다 — 서버에도 해시만 있다
   - 발급 폼의 「만료일 (선택)」은 날짜 입력이다. 비우면 만료 없음, 고르면 **그날 끝까지** 유효하다(브라우저 시간대의 다음 날 00:00을 보낸다). 과거 날짜를 거부한 서버의 400 문구는 그대로 보인다 (ADR-061 결정 1, #199)
   - 목록에 「만료」·「마지막 사용」 열을 둔다. 만료 시각은 「YYYY-MM-DD HH:MM까지」로 보이고, 로컬 자정 정각 만료는 시각 없이 그 전날 「YYYY-MM-DD까지」로 적는다(날짜 입력으로 고른 날). 만료 여부는 브라우저 시계가 아니라 서버의 `expired`로 판정해 「만료」 배지를 붙이며, 만료된 행도 폐기 전까지 목록에 남는다. 마지막 사용이 없으면 「사용 기록 없음」. 「마지막 사용」은 성공한 요청 기준이며 1분 단위다
   - 비밀번호를 바꾸면 모든 기기의 로그인이 끊긴다. **성공 안내는 `/login`이 띄운다** — 이 화면은 보호 경로라 세션이 끊기는 순간 `RequireAuth`가 밀어내므로 여기 둔 안내는 아무도 보지 못한다
   - 비밀번호를 **잊은** 경우는 이 화면으로 풀 수 없다. 운영자가 `openarchive reset-password`를 쓴다
8. `/trash` — **내가 지운 문서만** 제목·삭제 일시·영구 삭제 예정일로 보인다(관리자에게도 남의 문서는 없다). 홈 폴더 트리 아래 「휴지통」 링크로 들어간다. 행마다 「복원」과 「영구 삭제」 — 영구 삭제는 확인창(「삭제하면 되돌릴 수 없습니다.」)을 거친다. 문서 상세의 「삭제」 확인창은 「휴지통으로 옮깁니다. 30일 뒤 영구 삭제됩니다.」이며, 정적 빌드라 보존 기간 설정과 무관하게 30일로 고정한다 (ADR-060)

> 사용자 화면은 **인프라 상태를 일절 노출하지 않는다.** 페일오버가 일어나도 화면 구성은 달라지지 않으며, 사용자는 업로드와 검색이 계속 성공하는 것만 본다.
>
> **재시도 중 안내**: 읽기 요청이 503·네트워크 오류로 백오프 중일 때만 본문 위에 「연결이 원활하지 않아 다시 시도하는 중입니다.」를 보조 텍스트(`text-neutral-400`, `role="status"`)로 띄우고, 요청이 끝나면 치운다. 오류 색·경고 아이콘을 쓰지 않고, DB·노드·장애·페일오버 같은 말을 넣지 않는다 — 사용자에게 필요한 것은 "기다리면 된다"뿐이다. 60초 안에 풀리지 않으면 각 화면의 기존 오류 표시로 넘어간다. 화면을 떠나면 그 화면의 재시도는 취소되어 안내도 함께 사라진다. `/admin/status`는 예외다 — 관측 채널이라 실패를 기다리지 않고 바로 보인다 (ADR-048 결정 4).

> 검색 결과의 링크는 **문서 상세 화면으로** 간다. 원본 파일로 가지 않는다 — 검색·편집·버전의 단위가 원본 파일이 아니라 문서 텍스트이기 때문이다(아래 용어 규칙). 원본 파일은 문서 상세의 「원본 파일」 절에서 내려받는다.

검색 결과 카드의 「검색된 본문 대목 N개」를 펼치면 첫 발췌 밖에서 검색된 대목도 읽을 수 있다.
대목은 서버의 순서와 전체 문맥을 유지하고 **텍스트 버전**을 함께 표시한다. 자동 정답 선택이나
답변으로 표시하지 않는다. 후보가 없는 결과와 연결된 문서에는 빈 펼치기를 만들지 않는다.

### 근거 기반 답변 패널 (`/search`, ADR-043)

검색 결과와 별개인 옵션 레이어다. 검색 결과는 답변 여부와 무관하게 그대로 아래에 남는다.

- **로그인 사용자에게만**, 검색을 한 번 한 뒤에 보인다(`/api/ask`는 익명에게 401이므로 버튼을 보이지 않는다). 새 검색을 하면 이전 답변은 지운다.
- 답변은 자동으로 만들지 않는다. 「이 검색어로 답변 받기」 버튼을 눌러야 요청하며, **마지막 검색의 입력(질의·필터)** 으로 묻는다 — 폼을 고쳐도 화면에 보이는 결과 기준이다.
- 제목 「근거 기반 답변」 아래에 「검색된 문서만 근거로 답하도록 지시합니다. 보장은 아닙니다 — 인용한 근거를 확인하세요.」를 항상 둔다.
- 생성 중에는 버튼 대신 「답변을 만드는 중… 로컬 모델은 수십 초 걸릴 수 있습니다.」를 보인다. 요청 자체가 실패하면 오류 색으로 알리고 버튼으로 다시 요청할 수 있다.
- 답의 `[번호]`는 해당 근거의 **그 텍스트 버전의 그 대목**(`/documents/{id}?version=&chunk=`)으로 가는 링크다. 근거에 없는 번호는 모델이 지어낸 것이라 링크로 바꾸지 않고 글자 그대로 둔다.
- 답 아래에 **인용한 근거**를 번호·제목·버전·발췌로 나열한다. 버전은 「v3 기준」, 그 뒤 개정됐으면 「v3 기준 · 현재 v4」로 함께 보인다. 모델에 줬지만 인용하지 않은 근거는 「인용하지 않은 근거 N건」으로 접어 둔다.
- 답하지 않은 상태는 오류 색 없이 보조 텍스트로 알린다 — 꺼져 있음(「답변 생성이 설정되지 않았습니다. 관리자가 ANSWER_PROVIDER=ollama로 켤 수 있습니다. 검색 결과는 그대로 쓸 수 있습니다.」), 근거 없음(「근거로 쓸 문서를 찾지 못했습니다.」), 생성 실패(서버의 고정 문구 + 「검색 결과는 아래에 그대로 있습니다.」).


### 외부 공유 (`/settings`, #97 c)

공유 소유자의 세션으로 관리한다. 공유 생성·삭제(확인창), 포함 문서 목록(id·제목)과 빼기,
공유 토큰 발급·메타데이터 목록·개별 폐기를 제공한다. 토큰 원문은 발급 직후 한 번만 표시한다.
공유 토큰도 「만료일 (선택)」로 발급하며, 토큰 줄에 「만료」 배지(서버 `expired`)·만료 시각(「만료 없음」 또는
「만료 YYYY-MM-DD까지」)·「마지막 사용」(없으면 「사용 기록 없음」)을 보인다 — 규칙은 위 `/settings` API 토큰과 같다 (#199).
삭제 확인창은 공유의 토큰과 문서 부여도 함께 사라짐을 알린다. 공유에는 자기 문서만 넣으며,
문서 상세 「열람 범위」의 「내 공유에 포함」에서 추가한다. 공유 토큰의 접속은 REST 전용이다.

### 용어 규칙 — 원본 파일과 추출 텍스트를 구분한다

업로드된 PDF·DOCX·HWP·HWPX·XLSX·PPTX는 텍스트를 추출해 저장하고, 원본 파일은 편집하지 않은 채 판으로 따로 보관한다(ADR-017, ADR-046). 편집·버전 관리의 대상은 추출 텍스트다. 화면 문구가 이를 뭉뚱그리면 "PDF를 편집한다"는 오해가 생긴다.

| 화면에 쓸 말 | 쓰지 말 것 | 이유 |
|---|---|---|
| 문서 텍스트 | 본문, 원문 | `documents.content`의 상위 개념. 원본 파일이 없는 문서(`filename` 없음)의 편집 영역 레이블 |
| 추출 텍스트 | 본문, 원문 | 원본 파일과 구분되지 않는다 |
| 텍스트 버전 이력 | 문서 버전 이력 | 파일 버전 이력으로 읽힌다 |
| 되돌리기 | 롤백, 복구 | 이력을 되감아 지운다는 뜻으로 읽힌다. 실제로는 새 버전이 생긴다 (ADR-037) |
| 원본 파일 | 원문, 첨부 | 업로드한 파일 그 자체. 편집하지 않으며 교체하면 판으로 쌓인다 (ADR-046) |
| 판 (`N판`) | 버전, v{n} | 원본 파일의 버전이다. 텍스트 버전(`v{n}`)과 다른 말이라 번호 표기도 가른다 |
| 문서 상세 링크 | 원문 링크 | 원본 파일로 가지 않는다 |

`filename`이 없으면 추출한 원본 파일도 없으므로 편집 영역을 **"문서 텍스트"**로 표시한다.
`filename`이 있으면 기존대로 **"추출 텍스트"**를 쓴다 (ADR-035).

### 열람 범위 · 업로드 대상 선택 (ADR-044, #97 b 구현 계약)

- 화면의 공개범위 값은 **「조직 공개 / 제한」**으로 통일한다. 저장·API 값은 각각 `public`/`private`를 유지한다.
- 업로드의 기본값은 「조직 공개」다. 「제한」을 고르면 사용자명·그룹명으로 대상을 선택한다.
- **폴더를 고르면 열람 범위는 「폴더 범위 따름(…)」 하나다** (ADR-054, #187). 괄호 안에 그 폴더의 실효 범위(최상위 폴더의
  「조직 공개」 또는 「제한 · 사용자·그룹」)를 보인다 — 폴더 목록 응답의 `scope`다. 업로드에서 「개별 지정」은 고를 수 없고
  (서버도 개별 범위 인자를 거부한다), 문서 상세의 「열람 범위」 패널에서 바꾼다. 폴더 트리·범위 패널·확인 안내의 화면
  상세는 아래 「폴더」 절(2026-10-07, #187 c)이다.
  대상 목록은 로그인 사용자가 조회하는 조직 디렉터리(`GET /api/principals`)를 쓴다.
  대상을 선택하지 않은 제한 문서는 소유자만 본다. 조직 공개에는 사용자·그룹 부여 대상을 보내지 않는다.
- 문서 상세의 **「열람 범위」 패널은 소유자에게만 표시**한다. 현재 범위와 사용자·그룹 부여를
  조회하고, 저장하면 `{visibility, users, groups}` 전체를 교체한다. 변경은 로그인 세션으로만 한다.
- 제한 → 조직 공개로 바꾸면 사용자·그룹 부여 대상은 지워지고 공유 부여는 유지된다는 점을 안내한다.
- 소유자의 열람 범위 패널에 **「내 공유에 포함」** 체크를 둔다(#97 c). 조직 공개·제한 둘 다에서
  보이며, 체크로 자기 공유에 문서를 넣거나 뺀다. 열람 범위 저장과 독립적으로 즉시 반영한다.
- 그룹을 선택하는 곳에는 「그룹 구성원은 관리자가 변경할 수 있습니다. 관리자도 보면 안 되는
  문서는 사용자에게 직접 부여하세요.」라고 안내한다. 문서를 볼 수 있는 비소유자에게는 패널을
  보이지 않으며, API도 403으로 거부한다. 문서 자체를 볼 수 없으면 404다.

### 폴더 (ADR-054, 2026-10-07 화면 구현 #187 c)

**범위 라벨 형식** — 폴더 화면 어디서나 같은 형식을 쓴다. 조직 공개는 「조직 공개」, 제한은 대상이 없으면 「제한」,
있으면 「제한 · 」 뒤에 그룹들과 사용자들을 `, `로 잇는다(예: 「제한 · 사업팀, lee」). 상속을 말할 때는 괄호로 감싸
「폴더 범위 따름(제한 · 사업팀)」·「상위 폴더 범위 따름(조직 공개)」로 쓴다. 폴더 경로는 `/`를 공백 없이 써서 「인사/채용」으로
적는다.

- **트리 위치·선택 상태**: 홈(`/`) 왼쪽에 폴더 트리를 둔다 — 맨 위 「전체 문서」와 「새 폴더」, 하위 폴더는 상위 아래 계층으로,
  각 폴더 옆에 문서 수(그 폴더에 직접 든, 내가 볼 수 있는 문서). 좁은 화면에서는 목록 위로 쌓인다. 고른 폴더는 URL
  `?folder=<id>`에 두어 뒤로 가기·문서 상세의 경로 링크가 그 폴더로 돌아온다. 폴더를 고르면 목록·건수가 그 폴더에 직접 든
  문서로 좁혀진다. 문서 목록에 폴더 열은 두지 않는다 — 목록 요약에 폴더 정보를 싣지 않는 것이 누출 방지 설계다.
- **폴더 헤더**: 폴더를 고르면 목록 위에 경로와 범위 표시(최상위는 자기 범위, 하위는 「상위 폴더 범위 따름(…)」), 버튼
  「하위 폴더」·「이름 변경」·「삭제」, 최상위 폴더에만 「열람 범위」를 둔다. 이름 입력은 모달 없이 그 자리 입력칸이다.
  삭제는 확인창(「빈 폴더만 삭제할 수 있습니다」)을 거치고, 서버 오류 문구(「폴더가 비어 있지 않습니다.」 등)를 그대로
  `role="alert"`로 보인다.
- **거부는 서버가 보인다**: 폴더를 볼 수 있는 사람에게 「이름 변경」·「삭제」·「열람 범위」 버튼을 **숨기지 않는다.** 권한이
  없으면 버튼 곁에 「폴더를 만든 사람만 바꿀 수 있습니다」를 미리 보이고, 그래도 저장하면 서버의 403 문구 「폴더를 관리할
  권한이 없습니다.」를 그대로 보인다 — 시도할 수 있어야 거부를 시연할 수 있고, 경계는 서버가 지킨다. **문서의 「열람 범위」
  패널은 이와 다르다** — 지금처럼 소유자에게만 보인다(위 절).
- **폴더 범위 패널**: 최상위 폴더에만 둔다. 「조직 공개 / 제한」과 사용자·그룹 선택. 대상 없는 「제한」에는 「대상을 고르지
  않으면 폴더를 만든 사람만 봅니다」, 저장 근처에 「폴더 범위를 따르는 문서(다른 사람이 넣은 문서 포함)에 바로
  적용됩니다」를 보인다. 하위 폴더에는 패널이 없고 헤더의 「상위 폴더 범위 따름(…)」만 있다. 범위 변경은 로그인 세션으로만
  하며, 관리자도 남이 만든 폴더의 범위는 바꾸지 못한다.
- **업로드**: 「폴더」 선택(기본값은 홈에서 고른 폴더, 「폴더 없음」 가능). 폴더를 고르면 열람 범위 칸이 「폴더 범위
  따름(…)」으로 바뀌는 것이 안내이며 확인창은 띄우지 않는다. 남이 만든 폴더면 「폴더를 만든 사람이 범위를 바꾸면 이 문서에도
  적용됩니다」를 덧붙인다.
- **문서 상세**: 문서가 든 폴더를 볼 수 있으면 경로(「인사/채용」, 각 조각이 `/?folder=<id>` 링크)를 보인다. 볼 수 없으면
  (`folder: null`) **아무것도 그리지 않는다** — 🔒·「알 수 없는 폴더」 같은 자리도 두지 않는다(ADR-027). 폴더 옮기기는
  소유자에게만 보인다. **예외는 소유자 자신**이다 — 자기가 넣은 폴더의 범위를 만든 사람이 좁혀 폴더가 안 보이게 되면
  (`hidden_folder: true`, 소유자에게만 온다) 폴더 자리에 「볼 수 없는 폴더」라고 이름 없이 알리고, 「열람 범위」 패널도 「폴더 범위
  따름(볼 수 없는 폴더) / 개별 지정」으로 폴더 안 문서처럼 다룬다. 「폴더 없음」으로 옮기기도 그대로 할 수 있다. 숨은 폴더의
  범위는 알 수 없으므로 「폴더 범위 따름」 문서를 옮기면 늘 「볼 수 없는 폴더의 범위」에서 바뀐다는 확인창을 띄운다.
- **확인 안내(이동)**: 「폴더 범위 따름」 문서를 옮겨 실효 범위가 바뀔 때만 「열람 범위가 바뀝니다: 「A」 → 「B」.」 확인창을
  띄운다(라벨 끝이 사용자·그룹 이름이라 조사를 붙이지 않는다). 「개별 지정」 문서나 범위가 같은 이동은 확인 없이 옮긴다.
- **상속 전환**: 폴더 안 문서의 「열람 범위」 패널(소유자 전용)에 「폴더 범위 따름(…) / 개별 지정」을 둔다. 「폴더 범위
  따름」이면 공개범위 칸을 감춘다.
- **목록·상세의 「열람 범위」 표시**: 문서 자신의 `visibility`가 아니라 실제로 적용되는 `effective_visibility`를 보인다.
  폴더로 만든 문서의 자기 범위는 「제한」으로 닫혀 있어, `visibility`를 보이면 조직 공개 폴더 안 문서가 「제한」으로 잘못
  보인다(2026-10-07 실사용 점검).
- **대상 선택 안내**: 폴더 범위 패널의 대상 선택 안내는 폴더용(「…이 폴더와 폴더 범위를 따르는 문서를 봅니다」)이다 — 문서용
  「…소유자만 봅니다」를 쓰지 않는다.
- **폴더 고르기**: 업로드·이동·검색이 같은 선택 상자를 쓴다 — 평평한 목록, 라벨은 전체 경로(「인사/채용」), 트리 순서(부모
  다음 자식, 같은 층은 이름순).
- **검색**: 「폴더」 선택(「전체 폴더」 기본). 같은 폴더가 검색과 근거 기반 답변 양쪽에 걸리며, 「폴더는 직접 맞은 결과에만
  걸립니다(하위 폴더 포함). 관계로 이어진 결과는 폴더 밖 문서일 수 있습니다.」를 안내한다. 볼 수 있는 폴더가 없으면 선택을
  보이지 않는다.
- **갱신**: 폴더 생성·이름 변경·삭제·범위 저장·업로드·문서 이동 뒤 폴더 목록(문서 수)을 다시 불러온다.
- **감사 로그 라벨**: `folder_access_changed`는 「폴더 열람 범위 변경」, 설명은 「조직 공개 → 제한」 또는 「그룹 사업팀 추가」·
  「사용자 lee 제거」, 대상 칸은 「폴더 「RFP」」. 문서의 상속 전환은 「폴더 범위 따름 → 개별 지정」, 폴더 이동은 「폴더
  「인사」 → 「RFP」」(폴더 밖은 「폴더 없음」).

### 소유자 이전 (#200)

문서 상세의 「소유자」 패널은 소유자에게만 보인다. 「이전받을 사용자」에서 자신을 제외한 사용자를 고르고
「소유자 이전」을 누르면 이전 후에는 열람 범위대로만 보며 이전 소유자의 외부 공유에서 문서가 빠진다는 확인창을 보인다.
이전 뒤에도 보이면 상세를 갱신하고, 안 보이면 문서 목록(`/`)으로 간다.
폴더 헤더의 「소유자 이전」은 볼 수 있는 폴더에 보이지만 만든 사람만 실행할 수 있다(관리자 우회 없음).
「이전」 확인창은 하위 폴더·문서 소유자가 바뀌지 않음을 알린다. 안 보이게 되면 폴더 선택을 해제한다.
관리자 사용자 목록은 「삭제」가 409로 거부되면 해당 줄에 거부 문구와 「이전받을 사용자」·「이전 후 삭제」를 펼친다.
이전은 세션 전용이고 「소유자 변경」으로 감사에 표시한다.

### 문서 텍스트 편집 (`/documents/[id]`)

정합성 파이프라인을 화면에서 직접 보여주는 장치다. 한 문장을 고치고 저장하면 상태 배지가 `pending → processing → ready`로 바뀐다.

- **편집 영역 레이블은 원본 파일이 있으면 "추출 텍스트", 없으면 "문서 텍스트"**다 (위 어휘 표). `content_type`이 `pdf`·`docx`면 편집 영역 위에 안내를 **상시 표시**한다 (접었다 펴는 툴팁이 아니라 항상 보이는 한 줄):

  > 원본 파일이 아니라 업로드 시 추출된 텍스트를 편집합니다. 저장하면 새 텍스트 버전이 만들어집니다.

- 보기 ↔ 편집 **토글**. 편집 중에는 저장·취소만 노출하고 삭제는 비활성화한다
- 저장 시 화면이 읽어온 `version`을 함께 보낸다. **409를 받으면 덮어쓰지 않는다**:

  > 다른 곳에서 문서가 수정되었습니다. 새로고침 후 다시 시도하세요.

  편집 내용을 지우지 말고 화면에 남긴다 — 사용자가 복사해 둘 수 있어야 한다
- 저장 후 2초 폴링으로 상태 배지를 갱신한다. 배지 색은 기존 시맨틱 색을 그대로 쓴다

### 원본 파일 (`/documents/[id]`)

문서 메타데이터 아래, 텍스트 편집 위에 둔다 (ADR-046).

- **판 목록**: `N판` · 파일명 · 크기(십진 KB/MB) · 올린 날짜 · 그 판이 만든 `텍스트 v{n}`. 최신 판에 「현재」 표시
- **내려받기**: 최신 판과 이전 판 모두. 브라우저가 링크로 직접 받는다 — 내려받기 경로는 서버가 항상 내려받기로만 보낸다
- **미리보기**: 판정은 서버가 판마다 주는 `preview_status` 하나로 한다 — 화면은 확장자 목록을 따로 갖지 않는다. `ready`면 「내려받기」 앞에 「미리보기」를 둔다. 새 탭(`target="_blank" rel="noopener noreferrer"`)에서 미리보기 경로를 열어 내려받지 않고 브라우저가 보인다. PDF·PNG·JPG·JPEG는 원본이, HWP·HWPX·DOCX·XLSX·PPTX는 서버가 만든 변환본 PDF가 열린다. `pending`이면 링크 대신 「미리보기 준비 중」(보조 텍스트)을 적고, `failed`·`unavailable`·`null`이면 「내려받기」만 있다. 공유 토큰으로는 열 수 없다 (ADR-058, 2026-10-08 구현 #190 · 변환본 #228)
  - 변환본은 원본을 그린 결과이지 원본이 아니다 — 변환본을 「원본」이라 부르지 않는다. 글꼴 대체로 글자 모양이 원본과 다를 수 있다
- **새 파일로 교체**: 확인창을 거친다. 이전 원본은 판 목록에 남고, 추출 텍스트가 달라지면 새 텍스트 버전이 된다. 409·상한 초과는 편집과 같은 방식으로 알린다. 50MB 상한은 전송 전에 검사한다
- **원본에서 다시 추출**: 확인창에서 직접 고친 추출 텍스트가 새 버전으로 덮이고 이전 내용은 버전 이력에서 되돌릴 수 있음을 알린다. 결과가 같으면 오류가 아니라 「새 버전을 만들지 않았습니다」 안내다
- **원본이 없는 문서**(이 기능 이전 업로드·텍스트 공급 문서)는 「원본 파일이 없습니다」와 「원본 파일 올리기」만 보인다. 다시 추출 버튼은 두지 않는다
- 텍스트 편집 중에는 교체·다시 추출을 비활성화한다
- 판의 텍스트가 아직 인식되지 않았으면 `텍스트 v{n}` 자리에 「텍스트 인식 전」을 적는다

### 텍스트 인식 중 (`/documents/[id]`)

이미지·스캔 PDF는 워커가 텍스트를 인식하는 동안 문서 텍스트가 비어 있거나(새 문서) 이전 텍스트다(재추출·교체). 인식 결과가 사람이 고친 텍스트를 덮지 않도록 서버가 텍스트를 바꾸는 요청을 409로 막으므로, 화면도 미리 막는다 (ADR-052 결정 7).

- 「텍스트 인식 중」인 동안 **텍스트 편집·되돌리기·다시 추출·원본 교체를 비활성화**하고, 이유를 보조 텍스트로 상시 표시한다:

  > 원본에서 텍스트를 인식하는 중이라 텍스트 편집·되돌리기·다시 추출·원본 교체를 할 수 없습니다.

- 태그·삭제는 막지 않는다
- 인식 중에도 2초 폴링을 계속한다 — 인식이 끝나면 새로고침 없이 추출 텍스트가 나타난다
- 「텍스트 인식 실패」로 문서 텍스트가 비어 있으면 편집기 대신 「원본에서 텍스트를 인식하지 못했습니다. 원본을 교체하거나 다시 추출해 보세요.」를 보인다. 이전 텍스트가 남아 있으면 그것을 보이고 마지막 인식이 실패했음을 알린다
- 다시 추출이 인식 대기로 넘어가면 「새 버전을 만들지 않았습니다」 안내를 띄우지 않는다 — 결과가 아직 없다

### 텍스트 버전 되돌리기 (`/documents/[id]`)

버전 이력이 기록에 그치지 않고 되돌릴 수 있는 지점이 되게 한다 (ADR-037).

- 이력의 각 행에서 **그 버전의 본문을 펼쳐 본다.** 현재 버전 행에는 되돌리기를 노출하지 않는다 — 이미 그 내용이다
- 되돌리기는 **되감기가 아니라 새 텍스트 버전 생성**이다. 버튼과 확인 문구가 이를 드러내야 한다:

  > v{n}의 내용으로 새 텍스트 버전을 만듭니다. 이력은 지워지지 않습니다.

- **"롤백"·"복구"를 쓰지 마라.** 이력이 사라지거나 버전 번호가 되감긴다는 오해를 만든다. 이 플랫폼에서 버전 이력은 정합성의 증거라 append-only다
- 되돌리기도 화면이 읽어온 `version`을 함께 보낸다. 409 문구와 처리는 편집과 같다
- 되돌린 뒤에는 편집과 같이 상태 배지가 `pending → processing → ready`로 바뀐다 — 복원도 재임베딩을 거친다

### 텍스트 버전 비교 (`/documents/[id]`, 2026-10-08 구현 #190)

- 버전이 둘 이상이면 각 버전 줄에 체크박스를 둔다. **정확히 두 개**를 고르면 「비교」가 켜지고, 낮은 버전을 기준(base)으로 비교한다. 두 개를 고른 뒤에는 나머지 체크박스를 비활성화한다
- 현재가 아닌 버전 줄에 「현재와 비교」를 둔다 — 그 버전을 기준으로 현재 버전과 비교한다
- 결과 패널 제목은 「v{base} ↔ v{target} 비교」. 추가된 줄은 `+ ` 초록(`text-green-400`), 삭제된 줄은 `− ` 빨강(`text-red-400`), 맥락 줄은 회색이고 고정폭 글꼴로 보인다. 바뀐 곳 앞뒤 3줄만 맥락으로 보이며 떨어진 덩어리 사이에는 「…」를 둔다
- 두 텍스트가 완전히 같으면 「두 버전의 내용이 같습니다.」 — 되돌리기로 만든 버전과 원래 버전이 그 예다
- 서버가 비교 상한을 넘어 계산하지 않았으면(`too_large`) 「문서가 커서 비교 결과를 표시할 수 없습니다. 각 버전의 「본문 보기」로 확인하세요.」 — 바뀐 줄이 아주 많은 경우(약 1,100줄 이상, 문서를 통째로 바꾼 경우 등)다(ARCHITECTURE 텍스트 버전 비교의 작업량 예산)
- 비교의 대상은 텍스트 버전이지 원본 파일이 아니다. 비교는 서버가 하므로 화면은 줄을 다시 계산하지 않는다

### 관련 문서 · 태그 추천 (`/documents/[id]`)

#### 관계 종류 어휘

저장값은 화면에 직접 노출하지 않고 아래 표현을 쓴다. 관계는 자동 판정된 추천이므로 사실처럼
단정하지 않는다. 현재 ADR-029가 저장하는 값은 `overlaps`와 `related`이며, `points_to`와
`broader`는 이후 화면에서도 어휘가 갈리지 않도록 예약해 둔다.

| 저장값 | 화면 표현 |
|---|---|
| `overlaps` | 여러 대목에서 만난다 |
| `points_to` | 이 대목에서 만난다 |
| `broader` (내가 `src`) | 더 자세한 문서 |
| `broader` (내가 `dst`) | 더 포괄적인 문서 |
| `related` | 관련 있음 |
| `refers` | 본문에서 가리킨다 |

본문 `[[…]]` 위키링크의 표시 문구는 첫 `|` 뒤 별칭이 있으면 별칭, 없으면 링크에 적힌 그대로
(`[[폴더/제목#절]]`이면 「폴더/제목#절」)이며, 깨진 링크도 같은 문구를 쓴다.

**덩어리는 자동 판정된 묶음이므로 "주제"나 "분류"로 단정하지 않는다.** 「관계 지도」의 「미분류」는 태그가 없는 문서가 아니라 **관계가 없는 문서**를 뜻한다 — `/diagnostics`의 「미분류」(태그가 없는 문서)와는 다른 집계이므로 두 화면의 값이 서로 다를 수 있다 (ADR-042). 덩어리 이름이 예약 이름과 겹치면 출처를 밝혀 「미분류 (태그)」·「미분류 (문서)」로 적는다 — 화면이 덩어리 이름을 원과 선의 식별자로 쓰기 때문이다. **덩어리 이름은 최다 태그가 아니라 군집에 집중된 태그다** — (군집 안 빈도 − 밖 빈도)가 양수인 태그 중 최대이며, 코퍼스 전체에 퍼진 태그(「2025판」·「경영지원」)가 여러 덩어리의 이름을 독점하지 못한다 (ADR-042 개정).

- **`overlaps`를 "같은 내용"으로 부르지 않는다.** 판정은 **양쪽** 문서 각각의 대목 중 상대에서 최근접 이웃을 찾은 비율이 모두 0.8 이상이고 **양쪽 다 세 대목 이상**이어야 성립하며(저장된 `score`는 계산 주체 쪽 비율이다), 이웃 판정이 순위 기반이라 절대 거리 임계가 없다. 주제가 가까운 문서끼리는 모든 대목이 서로 최근접이 되어 비율이 1.0에 붙는다 — 실 BGE-M3 실측에서 `PRD`↔`UI 디자인 가이드`, `ADR-020`↔`고가용성(HA) 전략`이 모두 1.00이었다(`OPENSQL_RESEARCH.md` §14). 그래서 `points_to`("이 대목에서")와 같은 축에 두고 **대목 수만 달리 말한다**. 진단 화면은 그 비율을 **적지 않는다** — 진단의 임계(0.95)를 넘는 값이 실측상 전부 1.00이라(1.00 208건, 그다음이 0.90) 같은 `100%`가 줄마다 반복될 뿐 정보를 담지 않는다(#79 ③). 비율은 API 응답(`score`)에만 남긴다
- `broader`는 방향에 따라 표현을 반드시 가른다. 한 이름으로 뭉치면 관계에 저장한 방향이 사라진다
- **`refers`만은 단정한다.** 다른 값과 달리 `document_edges`가 아니라 본문의 `[[제목]]`에서 나온다 — 사람이 직접 쓴 것이라 추천이 아니다(ADR-030). 어휘를 비워 두면 `relationLabel`이 「관련 있음」으로 떨어뜨려 사람이 만든 관계가 유사도 추천처럼 보인다
- 검색의 직전 텍스트 버전 확장은 `이전 텍스트 버전`으로 표시한다
- **관계로 확장된 검색 결과에는 유사도를 표시하지 않는다.** 확장 행의 거리는 진입점 거리에 고정 페널티를 더한 값이라 `1 − 거리`가 음수가 되고, 같은 진입점에서 나온 확장은 전부 동점이다. 정렬을 위한 값이지 유사도가 아니므로 화면과 MCP 응답 어느 쪽에도 싣지 않고, 대신 **어디서 어떤 관계로 이어졌는지**를 보여준다. 직접 매칭의 유사도는 그대로 표시한다
- 종류별 점수는 척도가 다르므로 종류 사이의 순위를 비교하지 않고, 같은 종류 안에서만 정렬한다

- 각 관련 문서 항목에 **점수**와 **"v{n} 기준"**을 함께 표시한다. `based_on_version`은 "지금 보이는 결과가 몇 번 버전의 벡터에서 나왔는가"를 답하며, 버전 일관성 보장을 화면에서 뒷받침한다
- 문서 상세에서 태그를 직접 추가·삭제할 수 있고, 추천 태그를 클릭하면 현재 태그 목록에 추가된다. 추천은 제안일 뿐 자동 적용하지 않는다
- 태그 변경은 새 텍스트 버전을 만들거나 임베딩 상태 배지를 바꾸지 않는다
- **미색인 문서**(청크가 아직 없음 — 최초 업로드 직후 또는 임베딩 실패)에는 빈 목록 대신 안내를 노출한다:

  > 임베딩이 완료되면 표시됩니다.

  단 **텍스트 인식에 실패한 문서**(`extraction_status = failed`이고 청크가 없음)에는 임베딩이 오지 않으므로
  이 약속을 하지 않고 다음을 노출한다(ADR-052):

  > 텍스트를 인식하지 못해 표시할 수 없습니다.

  오류로 보이게 하지 않는다. 빨간색·경고 아이콘을 쓰지 않고 보조 텍스트(text-neutral-500)로 둔다

### 유사 문서 표시 — "중복"이라고 쓰지 않는다

유사도 점수는 비대칭 지표라 중복을 확정할 수 없다(ADR-018). 문구와 동작을 다음으로 제한한다.

| | 표시 | 동작 |
|---|---|---|
| `content_hash` 완전 일치 | "동일한 텍스트의 문서가 있습니다" | 링크만 제공 |
| 점수 상위 항목 | "내용이 유사한 문서가 있습니다" | 링크만 제공 |

- 업로드를 막거나, 자동 병합하거나, "중복" 배지를 띄우지 않는다
- 임계값으로 경고를 켜지 않는다. 관련 문서 목록에 점수를 함께 보여주는 것으로 충분하며, 판단은 사용자가 한다

### 관리 화면 (3화면)

`/admin/` 아래는 관리자 권한을 요구하는 자리다. 문서 진단은 사람마다 값이 다른 사용자 화면이므로 여기 두지 않고 `/diagnostics`에 둔다.

8. `/admin/users` — 계정 목록·발급·삭제. 관리자는 **계정과 그룹을 관리**하며, 그룹 구성원 변경은 그 그룹에 부여된 문서의 열람을 바꾼다(ADR-044 「관리 경로」). 사용자 직접 부여·소유자 문서의 경계는 유지한다. **남의 비밀번호를 바꾸는 경로는 두지 않는다** — 그 권한은 열람 경계를 무너뜨린다 (ADR-040)
9. `/admin/groups` — **그룹 관리**(관리자·세션 전용, #97 b). 그룹 생성·목록·삭제와 구성원 추가·제거. 이름이 부여 대상 지정 계약이므로 이름 변경은 두지 않는다. 그룹을 삭제하면 그 그룹의 부여도 사라져 제한 문서는 소유자·다른 부여 대상만 볼 수 있음을 안내한다.
10. `/admin/status` — 관리자 전용 관측 패널 (데모·운영 전용)
   - 현재 접속 DB 노드 (`inet_server_addr()`)
   - `pending` / `processing` / 「회수 대기」 / `error` **임베딩** 잡 수 (관계 잡은 여기 세지 않는다). 「회수 대기」는 lease가 만료된 `processing` 잡(`recovery_pending`) — 워커가 죽었거나 연결을 잃어 다음 스윕이 `pending`으로 되돌릴 잡이다. 그 아래에 「워커가 {lease}초 동안 처리 중임을 알리지 않은 잡은 회수됩니다.」를 둔다 (ADR-050)
   - **정합성 검증**: 원본 버전과 청크 버전이 어긋난 문서 수 (`c.version <> d.version`). 평상시 0, 재임베딩 중에만 증가했다가 다시 0으로 수렴한다 — **"원본-벡터 정합성"을 숫자로 보여주는 지표**
   - **관계 반영**: 관계가 아직 반영되지 않은 문서 수. 같은 정합성 카드 안에서 위 수와 나란히 두고 레이블(「원본과 청크 버전」 / 「관계」)로 가른다. 관계는 임베딩이 끝난 뒤 별도 잡으로 계산되므로 **0보다 큰 값 자체는 오류가 아니다** — 오류 색(`#ef4444`)을 쓰지 않고 `jobs.error`와 구분한다. 다만 관계 잡이 재시도를 소진해 `error`로 격리돼도 이 수에 계속 세므로, **설명 문구는 저절로 0이 된다고 단정하지 않는다** — 워커 확인과 `openarchive rebuild-edges` 복구 경로를 함께 안내한다 (ADR-029 결정 3 개정)
   - **텍스트 인식**: 인식 대기 문서 수와 인식 실패 문서 수 (`extraction_status`가 `pending`·`failed`). 실패 문서는 원본 교체나 `openarchive reextract`로 다시 돌린다 (ADR-052)
   - **미리보기 변환**: 대기·실패·변환기 없음 **판 수** (`document_file_previews.status`가 `pending`·`failed`·`unavailable`). 실패는 오류 색, 대기·변환기 없음은 기본 색이다. 변환기 없음이 0보다 크면 변환기(rhwp·LibreOffice)·한글 글꼴·bubblewrap 설치를 확인하고 `openarchive rebuild-previews`로 다시 걸라고 안내한다 (ADR-058)
   - 임베딩 프로바이더명
   - `error` 문서 목록 + 재임베딩 버튼 (`POST /api/documents/{id}/reembed`)

> 정합성 검증 카운터가 데모의 핵심 지표다. 문서를 수정하면 잠깐 1로 올랐다가 워커가 처리하면 0으로 돌아온다. 페일오버를 일으켜도 결국 0으로 수렴하는 것을 보여주면, 이 과제가 요구한 "장애 상황에서도 원본과 벡터의 정합성이 유지된다"를 한 화면으로 증명할 수 있다.

관리자 메뉴의 「시스템 상태」로 들어간다 — 일반 사용자 메뉴에는 없다(2026-10-08 구현 #190). 데모 시 사용자 화면과 나란히 띄워 "장애가 있었고, 복구됐고, 사용자는 몰랐다"를 한 화면에 담는다.
