# 비밀번호와 다단계 인증 기준

## 비밀번호 요건

최소 12자 이상으로 만든다. 영문 대소문자, 숫자, 특수문자를 섞는 규칙은 강제하지 않는다. 길이가 짧은 복잡한 문자열보다 긴 문장 형태가 실제로 더 안전하고 기억하기도 쉽다. 다만 사전에 있는 단어 하나만 쓰거나 회사명, 생년월일, 연속된 숫자는 막는다.

## 변경 주기

정기 변경을 요구하지 않는다. 주기적으로 바꾸게 하면 뒤에 숫자만 하나씩 올리는 방식으로 이어져 오히려 약해진다. 대신 유출 정황이 확인되면 즉시 바꾸게 한다.

## 재사용 금지

회사 계정의 비밀번호를 외부 서비스에서 쓰지 않는다. 외부 서비스가 털리면 회사 계정이 함께 뚫린다. 유출된 비밀번호 목록과 대조해 일치하는 것이 발견되면 해당 계정을 즉시 잠그고 재설정을 요구한다.

## 다단계 인증

모든 사내 시스템에 다단계 인증을 적용한다. 인증 앱의 일회용 번호를 기본으로 하고, 문자 메시지는 앱을 쓸 수 없는 경우에만 허용한다. 문자는 번호 이전 공격에 취약하므로 관리자 권한 계정에는 쓰지 않는다.

## 관리자 계정

서버, 데이터베이스, 결제 시스템의 관리자 계정에는 하드웨어 보안키를 추가로 요구한다. 대상과 발급 절차는 [[서버 접근권한 승인 절차]]에 있다.

## 분실과 초기화

인증 수단을 잃어버리면 정보보안팀이 본인 확인 후 초기화한다. 메신저나 메일 요청만으로 초기화하지 않는다. 이 절차를 건너뛰는 것이 사회공학 공격의 가장 흔한 통로다.

## 인증 앱 교체

휴대전화를 바꿀 때는 기존 인증 수단을 사용할 수 있는 동안 새 앱을 등록한다. 새 기기에서 인증이 되는지 확인한 뒤 이전 기기의 등록을 해제한다. 등록 화면에 나온 비밀값이나 복구 코드를 메신저로 보내지 않는다. 이전 기기를 이미 잃어버렸다면 일반 교체가 아니라 본인 확인을 거치는 초기화 절차로 처리한다.

## 예기치 않은 인증 요청

본인이 로그인을 시도하지 않았는데 인증 요청이 오면 승인하지 않는다. 반복해서 뜨더라도 알림을 없애려고 승인하지 말고 정보보안팀에 알린다. 담당자는 발생 시각과 접속 기록을 확인하고 필요하면 계정을 잠근다. 신고할 때 비밀번호나 일회용 번호 자체를 전달할 필요는 없다.

## 복구 코드 보관

복구 코드는 인증 앱을 사용할 수 없을 때를 위한 수단이므로 앱이 있는 기기에만 보관하지 않는다. 회사가 승인한 보관 위치에 두고 다른 사람과 공유하지 않는다. 코드를 사용했거나 노출이 의심되면 새로 발급해 이전 것을 무효화한다. 담당자는 복구 코드 원문을 상담 기록에 적지 않는다.

## 초기화 이후 확인

인증 수단을 초기화한 담당자는 요청자에게 새 수단 등록이 끝났는지 확인한다. 분실된 기기와 연결된 기존 수단이 남아 있지 않은지도 점검한다. 본인 확인 방법과 처리 시각은 남기되 인증 비밀값은 저장하지 않는다. 초기화 요청을 했다는 사실만으로 다단계 인증을 계속 면제하지 않는다.
