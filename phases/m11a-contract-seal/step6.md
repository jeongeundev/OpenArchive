# Step 6: adr-contract-seal

## 배경 — 근거 문서가 앞선 step들과 정반대를 말하고 있다

step 0이 주체 문서의 열람 검증을 서비스 계층으로 내렸다. 그런데 `docs/ADR.md:1091`(ADR-027)에는
이렇게 적혀 있다:

> **경계를 거는 자리는 HTTP 계층이다.** 열람 술어(`VISIBLE_TO_USER`)는 그대로 두고 읽기
> 엔드포인트가 `require_user_id`를 요구한다 (…) 술어를 고치면 `MCP_USER_ID`가 없는 설치에서
> MCP가 통째로 눈이 먼다.

`docs/ARCHITECTURE.md:672`도 마찬가지다:

> 대상 문서 자체의 접근 권한은 API 레이어의 문서 조회에서 이미 걸린다.

이 step은 코드를 고치지 않는다. **앞선 여섯 step이 만든 사실에 문서를 맞춘다.**

### ✅ 결정 1 — 새 ADR 번호를 만들지 않는다. ADR-027·028을 개정한다

**이 결정은 이미 닫혔다. 사용자가 명시적으로 승인했다. 다시 판단하지 말고 아래대로 진행하라.**

- 이번 작업은 새 결정이 아니라 **기존 결정의 적용 지점 이동**이다. 열람 술어도, 권한 모델도,
  인증 방식도 바뀌지 않았다.
- 뒤따르는 작업에 번호가 예약되어 있다 — **033=ZIP 업로드 · 034=프로그램 토큰 · 035=텍스트 API ·
  036=MCP 쓰기 도구**. 여기서 033을 쓰면 넷이 전부 밀린다.
- 이 저장소에는 개정 선례가 있다 (ADR-018 재개정, ADR-015의 *"2026-08-14 ADR-031이 결정 1을
  확장"* 표기). **그 서술 형식을 그대로 따르라.**

### 🔴 결정 2 — 원 결정이 지키려던 두 가지가 여전히 지켜짐을 밝혀라

ADR-027이 경계를 HTTP에 둔 이유는 두 가지였다. 개정문은 그 둘이 **깨지지 않았음**을 설명해야
한다. 설명 없이 결론만 뒤집으면 나중에 읽는 사람이 원 결정의 근거가 틀렸다고 오해한다.

1. *"기존 열람 술어를 바꾸지 않는다"* — 지켜졌다. `VISIBLE_TO_USER`는 한 글자도 바뀌지 않았다.
   달라진 것은 그 **동일한 술어를 주체 문서에도 적용**한다는 점이다.
2. *"MCP가 통째로 눈이 먼다"* — 일어나지 않는다. `MCP_USER_ID`가 없는 설치에서도 public 문서는
   그대로 보인다. 달라지는 것은 비공개 문서를 주체로 지정했을 때뿐이며, 그 경우 MCP는 이미
   `get_document`에서 `DocumentNotFound`를 받고 있었다 — 오히려 경로 간 동작이 일치하게 됐다.

아니라 코드가 사실의 출처다.

- `backend/app/services/system.py` — 새로 생긴 서비스
- `backend/app/api/system.py` — 인증이 걸린 라우터
- `backend/tests/test_architecture.py` — 계층 경계를 잠근 fitness test
- `docs/ADR.md` ADR-027(:1020~)·ADR-028(:1059~) — 개정 대상. ADR-015(:498)와 ADR-018의 **상태

- `docs/ARCHITECTURE.md` 「세 가지 공통 규칙」(:664~) — 낡은 문장이 있는 자리

## 작업

### 1) ADR-027을 개정한다

- **상태** 줄에 개정 표기를 더한다 (ADR-015:499 형식). 예:
  `2026-08-09 신규 (#35) · 2026-08-14 경계 위치 개정 (#63)`
- *"경계를 거는 자리는 HTTP 계층이다"* 문단을 개정한다. **원문을 지우지 마라** — 이 저장소의
  ADR은 판단이 바뀐 과정을 남긴다. 원 결정과 그 근거를 유지한 채, 무엇이 왜 바뀌었는지를
  덧붙이는 형식으로 쓴다.
- 개정 내용에 반드시 담을 것:
  - 주체 문서의 열람 검증이 **서비스 계층**으로 내려왔다는 사실과 그 자리(`ensure_visible`)
  - 바뀐 이유 — 인터페이스가 협조해야 계약이 성립하는 구조였고, 서비스를 직접 부르는 인터페이스가
    늘어날 예정이다 (PRD §4 경계 규칙)
  - 결정 2의 두 항목 (술어 불변 · MCP 무실명)
  - 라우터 선행 가드 4개를 제거했다는 사실과, 제거해도 REST가 404를 유지한다는 근거

### 2) ADR-028을 개정한다

- **상태** 줄에 개정 표기를 더한다.
- 읽기 엔드포인트 인증 목록에 **`/api/system/status`**를 추가한다. 원래 목록은
  *"검색·문서 목록·문서 상세·관련 문서·태그 추천·주제 덩어리·문서 진단"*이다.
- 함께 적을 것:
  - 무엇을 감추는가 — 노드 주소·포트, 잡 카운터, 정합성 어긋남 수, 프로바이더 이름
  - `/api/health`는 무인증으로 남는다는 것과 그 이유 (문서·토폴로지 정보가 없다)
  - `demo_recovery.sh`의 기동 대기가 `/api/health`로 옮겨졌다는 것. **이 한 줄이 없으면 다음
    사람이 같은 함정을 다시 밟는다** — status를 폴링하던 코드가 로그인보다 먼저 실행됐다

### 3) `docs/ARCHITECTURE.md`를 고친다

- `:672`의 *"대상 문서 자체의 접근 권한은 API 레이어의 문서 조회에서 이미 걸린다"*를 현재 사실로
  바꾼다 — 서비스가 스스로 검증한다.
- 시스템 상태 관련 서술이 있다면 `services/system.py` 신설을 반영한다. **문서 전체를 훑어
  `api/system.py`에 SQL이 있다는 전제로 쓰인 곳이 없는지 확인하라.**
- 서비스 목록·계층 그림이 있다면 새 모듈을 더한다.

### 4) `docs/PRD.md`를 확인한다

- §5 C2는 관측 가능성을 *"독립된 제품 표면"*으로 승격했다. 이번 단계로 그 쿼리가 서비스 계층에
  들어가 Web UI 밖에서도 소비 가능해졌다 — 이 사실을 반영할 자리가 있는지 보라.
- **C1~C5의 구현 상태 표기를 임의로 바꾸지 마라.** 상태 변경은 범위 판단이며 이 step의 권한
  밖이다. 바꿔야 한다고 판단되면 고치지 말고 summary에 적어라.

### 5) `CLAUDE.md` 아키텍처 규칙에 한 줄을 더한다

ADR-018·027을 인용한 CRITICAL 항목("볼 수 없는 문서는 존재하지 않는 것처럼 보인다") 근처에,
**주체 문서의 열람 검증은 서비스가 한다**는 규칙을 더한다. 다음 세션이 새 서비스 함수를 만들 때
이 규칙을 보고 `ensure_visible`을 부르게 하는 것이 목적이다.

- 새 CRITICAL 항목을 남발하지 마라. 기존 항목에 문장을 더하는 쪽이 나으면 그렇게 하라.
- **문서 파일을 새로 만들지 마라.** 갱신만 한다.

### 6) 과대 진술을 만들지 마라

이 저장소는 문서 과대 진술을 한 번 걷어낸 이력이 있다(#62). 다음을 지켜라:

- *"항상 최신"·"실시간 동기화"*를 쓰지 않는다. 보장 범위는 **버전 일관성 + 최신 수렴**이다 (ADR-015)
- *"완전히 봉인했다"·"모든 경로가 안전하다"* 같은 총괄 단언을 쓰지 마라. 봉인된 것은 이번에 다룬
  네 함수와 status 하나다. 사실을 세어서 써라
- CI에 대해 *"모든 변경이 검증된다"*로 쓰지 마라. 워크플로가 도는 것은 `check.sh` 범위이며 실
  OpenSQL·실 VM 데모는 CI 밖이다

## 검증 절차

1. 위 AC 커맨드를 순서대로 실행한다.
2. **문서에 적은 내용이 코드와 일치하는지 하나씩 대조하라.** 이 step에서 가장 흔한 실패는
   "그렇게 했어야 하는 것"을 "그렇게 되어 있는 것"으로 적는 것이다. 파일 경로·함수 이름·개수를
   적을 때는 반드시 코드에서 확인한 값을 써라.
3. 체크리스트를 확인한다:
   - 새 ADR 번호를 만들지 않았는가? (033~036은 예약되어 있다)
   - 원 결정의 근거를 지우지 않고 개정을 덧붙였는가?
   - 총괄 단언·과대 진술이 없는가?
   - 코드를 고치지 않았는가? (이 step은 문서 전용이다)
4. 결과에 따라 `phases/m11a-contract-seal/index.json`의 step 6을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- **새 ADR 번호를 만들지 마라.** 이유: 033=ZIP·034=토큰·035=텍스트 API·036=MCP 쓰기가 예약되어
  있다. 여기서 하나를 쓰면 넷이 전부 밀리고 이슈 본문의 번호 표기도 어긋난다.
- **ADR-027·028의 원 결정과 근거를 지우지 마라.** 이유: 이 저장소의 ADR은 판단이 바뀐 과정을
  남긴다. 결론만 갈아 끼우면 원 결정이 왜 그랬는지가 사라진다.
- **코드를 고치지 마라.** 이유: 이 step은 문서 정합 전용이다. 문서를 쓰다 코드 결함을 발견하면
  고치지 말고 summary에 적어라 — 그것이 다음 이슈의 재료다.
- **PRD의 C1~C5 구현 상태 표기를 임의로 바꾸지 마라.** 이유: 범위 판단이며 이 step의 권한 밖이다.
- **새 문서 파일을 만들지 마라.** 이유: 이 저장소의 문서 지도는 `CLAUDE.md`의 표가 관리한다.
  파일이 늘면 그 표도 함께 관리해야 하고, 이번 변경은 새 문서를 필요로 하지 않는다.
- **총괄 단언을 쓰지 마라.** 이유: 봉인된 것은 네 함수와 status 하나다. "모든 경로가 안전하다"는
  검증되지 않은 진술이며, 이 저장소는 그런 문장을 한 번 걷어낸 이력이 있다 (#62).
- **기존 테스트를 깨뜨리지 마라.**
