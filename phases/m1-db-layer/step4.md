## 배경

이 step은 **DB도 임베딩 모델도 필요 없는 순수 함수 하나**를 만든다. 워커가 문서 본문을 임베딩 가능한 조각으로 자를 때 쓴다.

순수 함수로 분리하는 이유는 워커의 나머지 부분(트랜잭션·잠금·재시도)과 독립적으로 검증하기 위해서다. 워커 테스트는 느리고 DB가 필요하지만, 청킹 규칙은 밀리초 단위로 수십 개의 경계 조건을 확인할 수 있다.

## 작업

### 1. `backend/app/services/chunking.py`

```python
def chunk_text(text: str, *, max_chars: int = 1000, overlap: int = 150) -> list[str]:
    """문서 본문을 임베딩 단위로 자른다. 문단 경계를 우선 존중한다."""
```

**분할 우선순위**: 문단 경계(빈 줄) → 그래도 `max_chars`를 넘으면 강제 분할.

**반드시 만족해야 하는 불변식** — 구현 방식은 재량이지만 아래는 전부 지켜야 한다:

1. 반환된 모든 청크의 길이가 `max_chars` 이하다. **오버랩으로 덧붙인 부분을 포함해서** 이하여야 한다.
2. **내용 누락이 없다.** 원문의 공백 아닌 모든 문자가 최소 한 개의 청크에 등장한다. 임베딩되지 않은 본문 조각이 남으면 그 부분은 영원히 검색되지 않는다.
3. 청크가 2개 이상이고 `overlap > 0`이면, **인접한 두 청크는 겹치는 텍스트를 공유한다.** 문장이 경계에서 잘려 의미를 잃는 것을 완화하는 장치다.
4. **결정론적이다.** 같은 입력에 같은 출력. 난수·시간·해시 순서에 의존하지 마라 — 재임베딩의 멱등성이 여기에 걸려 있다.
5. 텍스트가 비었거나 공백뿐이면 빈 리스트를 반환한다. (DB의 `CHECK (length(btrim(content)) > 0)`가 이미 막지만, 함수 자체가 안전해야 한다.)
6. 각 청크는 앞뒤 공백이 정리된 상태다.
7. **외부 의존성이 없다.** 표준 라이브러리만 쓴다. `langchain`·`tiktoken` 같은 패키지를 추가하지 마라.

**단위는 문자 수(`len`)다.** 토큰 수로 세지 마라 — 토크나이저를 부르면 모델 의존성이 생기고, 순수 함수가 아니게 된다. BGE-M3의 8192 토큰 한도에 1,000자는 충분히 여유가 있으므로 문자 기준으로 충분하다 (ADR-003).

### 2. `backend/tests/test_chunking.py` — 먼저 작성한다

**구현보다 테스트를 먼저 작성하고 실패를 확인한 뒤 구현하라.** DB가 필요 없으므로 빠르게 돌아간다. 경계 조건을 아끼지 말고 검증하라.

최소 아래를 확인한다.

1. **짧은 텍스트** — `max_chars` 이하 문장 하나는 청크 1개로 나오고 내용이 그대로다.
2. **빈 입력** — `""`와 공백/개행뿐인 문자열은 빈 리스트.
3. **긴 단일 문단** — 문단 경계가 없는 긴 텍스트가 여러 청크로 쪼개지고, **모든 청크가 `max_chars` 이하**다.
4. **오버랩 존재** — 인접 청크가 실제로 겹치는 문자열을 공유한다. "겹칠 것이다"가 아니라 **겹치는 구간을 실제로 비교하라.**
5. **누락 없음** — 원문에서 공백을 제거한 문자열이, 청크들을 이어붙여 공백을 제거한 문자열 안에 순서대로 모두 포함된다.
6. **문단 경계 존중** — `max_chars`에 여유가 있는 짧은 문단 여러 개는 문단 중간에서 잘리지 않는다.
7. **결정론** — 같은 입력으로 두 번 호출하면 결과가 동일하다.
8. **파라미터 커스텀** — `max_chars`·`overlap`을 작은 값으로 주어도 불변식 1·3이 유지된다. `overlap=0`도 동작한다.
9. **한국어** — 한국어 문단으로도 위 불변식이 유지된다. 이유: 실제 대상 문서가 한국어이며, 공백 기준 단어 분할 가정이 한국어에서 다르게 동작할 수 있다.

> **무한 루프를 조심하라.** `overlap >= max_chars`이면 전진 폭이 0 이하가 되어 슬라이딩이 멈추지 않는다. 이 경우를 어떻게 다룰지 정하고(예: 값 검증 후 예외) 테스트로 고정하라.

## 금지사항

- **청킹 라이브러리(`langchain`, `llama-index`, `tiktoken` 등)를 추가하지 마라.** 이유: 함수 하나에 프레임워크 의존성을 들이는 것은 과하고, `pyproject.toml`의 의존성 목록은 심사에서 읽힌다.
- **토크나이저로 길이를 세지 마라.** 이유: 모델 의존성이 생겨 순수 함수가 아니게 된다.
- **청킹 함수 안에서 임베딩을 만들거나 DB에 쓰지 마라.** 이유: 워커의 책임이다. 이 함수는 텍스트 → 텍스트 조각 변환만 한다.
- **문장 분리기(kss·konlpy 등)를 도입하지 마라.** 이유: 요청받지 않았고, 한국어 형태소 분석 의존성은 설치 비용이 크다. 문단 경계 + 문자 수로 충분하다.
- **`app/services/`에 다른 파일(`parsing.py`·`documents.py`·`search.py`)을 만들지 마라.** 이유: 각각 업로드·검색 phase의 범위다.
- **설정값(`max_chars`·`overlap`)을 `config.py`나 환경변수로 빼지 마라.** 이유: 요청받지 않은 설정 가능성이다. 기본 인자로 충분하다.
- 기존 테스트를 깨뜨리지 마라.
