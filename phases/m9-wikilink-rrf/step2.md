# Step 2: wikilink-frontend

## 배경 — 링크가 눌려야 위키다

step 1까지는 API 응답에만 링크가 있다. 이 step이 본문에서 `[[제목]]`을 **누를 수 있는 것**으로
바꾸고, 문서 상세에 **백링크**를 붙인다.

**깨진 링크도 보여야 한다.** 위키에서 깨진 링크는 *"여기에 문서가 있어야 한다"*는 표시이고,
#29가 이 기능을 *"사람이 만드는 층"*이라고 부른 이유가 그것이다.

## 읽어야 할 파일

- `docs/UI_GUIDE.md` — 화면 규칙. m7 step 9가 남긴 관계 어휘표도 여기 있다
- `frontend/src/app/documents/` — 문서 상세와 본문 렌더
- `docs/ADR.md` **ADR-027 결정 5** — 깨진 링크와 권한 없음이 **같아 보여야** 한다
- `backend/app/api/schemas.py` — step 1이 만든 응답 형태

## 작업

### 1) 테스트를 먼저 쓴다

- 본문의 `[[제목]]`이 링크로 렌더되는가
- **해석된 링크와 깨진 링크가 다른 모양인가** (누를 수 있는가 / 없는가)
- **깨진 링크에 사유가 표시되지 않는가** — "권한 없음" 같은 문구가 없어야 한다
- 백링크가 없을 때 화면이 비지 않는가
- 동명 문서가 여럿일 때 step 0의 결정대로 보이는가

### 2) 본문 렌더

- `[[제목]]`을 링크로 바꾼다. **해석 결과는 API가 준다** — 프론트가 제목으로 다시 찾지 마라
- **깨진 링크는 눌리지 않는 다른 스타일**로 보인다. 위키 관례대로 흐리거나 점선이면 충분하다
- **사유를 붙이지 마라.** 툴팁으로도 안 된다 — `title="권한이 없습니다"`가 정확히
  ADR-027이 막는 것이다

> ⚠️ **본문을 HTML로 만들 때 주입을 조심하라.** 추출 텍스트는 사용자가 올린 파일에서 왔다.
> 기존 렌더가 어떻게 이스케이프하는지 확인하고 **같은 방식을 쓴다.** 새로 만들지 마라.

### 3) 백링크

- 문서 상세에 **"이 문서를 가리키는 문서"** 영역
- 열람 범위 기준이라 **사람마다 다르게 보인다** — 정상이다
- 없으면 영역 자체를 만들지 않는다 (빈 자리를 남기지 마라)

### 4) 편집 화면 (step 0의 결정 1이 "쓴다"인 경우)

- 사용자가 `[[`를 칠 수 있어야 한다. **자동완성은 만들지 마라** — 있으면 좋지만
  코드 프리즈 전 마지막 phase다
- **문법 도움말 한 줄**을 편집 화면에 둔다. 모르면 아무도 안 쓴다

## Acceptance Criteria

```bash
cd frontend

# 1) 타입·린트·테스트
npm run lint && npm run build && npm test

# 2) 사유가 새지 않는가 — 출력이 없어야 한다
grep -rnE "권한이 없|권한 없음|비공개 문서" src/
grep -rniE "title=.*권한" src/

# 3) 해석을 프론트가 다시 하지 않는가 — 출력이 없어야 한다
grep -rnE "documents\.find|title ===" src/ | grep -i link

# 4) 눈으로 확인 — 이 step의 진짜 AC다
cd .. && docker compose up -d
(cd backend && uvicorn app.main:app --port 8000 &)
(cd backend && python -m app.worker &)
(cd frontend && npm run dev &)
#   → 브라우저에서. ⚠️ m8이 익명 읽기를 닫아(ADR-028) 로그아웃 상태로는 문서 화면
#     자체가 열리지 않고 /login으로 넘어간다. "볼 수 없는 시선"은 익명이 아니라
#     **그 private을 소유하지 않은 다른 계정**으로 만든다. 계정 둘을 미리 만들어 둘 것:
#     ADMIN_PASSWORD=... python scripts/create_admin.py alice --admin
#     ADMIN_PASSWORD=... python scripts/create_admin.py bob
#     · 본문의 [[제목]]이 눌리는가
#     · 없는 문서를 가리키는 링크가 깨진 모양으로 보이는가
#     · alice의 private을 가리키는 링크가 **bob에게** "없는 문서"와 똑같아 보이는가
#     · 백링크가 계정에 따라 달라지는가 (alice에게 보이던 것이 bob에게 없는가)
#     · 백링크가 없는 문서에서 빈 영역이 생기지 않는가

# 5) 전체 검증
bash scripts/check.sh
```

## 검증 절차

1. 위 AC 커맨드를 실행하고 **브라우저에서 직접 확인한다.**
2. 아키텍처 체크리스트를 확인한다:
   - **볼 수 없는 계정(bob)으로 봤을 때 private 링크와 없는 문서 링크가 정말 똑같아
     보이는가?** 색·툴팁·커서 어느 것도 달라선 안 된다. 익명으로는 화면이 열리지
     않으므로 이 확인을 익명으로 대신할 수 없다 (ADR-028)
   - **본문 렌더가 기존 이스케이프 방식을 그대로 쓰는가?**
   - **프론트가 링크를 다시 해석하지 않는가?** 하면 권한이 프론트로 새어 나온다
   - **빈 영역이 생기지 않는가?**
3. 결과에 따라 `phases/m9-wikilink-rrf/index.json`의 step 2를 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- **깨진 링크에 사유를 붙이지 마라.** 툴팁·색 구분·아이콘 전부 안 된다.
  이유: ADR-027 결정 5 — 구분 불가능한 것이 목적이다
- **프론트에서 제목으로 문서를 다시 찾지 마라.** 이유: 권한이 API 밖으로 새어 나온다
- **자동완성·링크 미리보기를 만들지 마라.** 이유: 코드 프리즈 전 마지막 phase이고
  3순위 기능이다
- **본문 이스케이프 방식을 새로 만들지 마라.** 이유: 추출 텍스트는 외부 입력이다.
  기존 방식을 쓴다
- **백링크가 없을 때 빈 영역을 남기지 마라.** 이유: 개수가 0인 것도 정보다 —
  다만 "0건"을 표시하는 것과 영역을 안 만드는 것은 다르다. 후자를 택한다
