## 작업

### 1) `docs/ADR.md` — ADR-046 신설 + 과거 ADR에 이동 주석

**ADR-046: 원본 파일은 DB 안 `bytea`로 판을 쌓아 보관한다** (상태: 2026-09-23 신규, #108). 담을 것:

- **배경**: 원본 비보관은 제품 원칙이었다(ADR-017·035, PRD §4). 2026-09-21 기업 멘토링에서 "미보관은 데이터
  유실"이라는 피드백 — 파서가 좋아져도 다시 추출할 수 없고, 오추출을 고친 뒤 돌아갈 원본이 없다.
- **결정 1 — 위치는 DB 안 `bytea`**: 파일시스템·오브젝트 스토리지 기각 사유. 원본·텍스트·버전·청크·벡터·
  관계·잡이 한 DB·한 트랜잭션·한 복제 스트림 — failover에 앱이 옮길 것이 없고 백업 하나가 플랫폼 전체다
  (#110 HA 실증이 이 주장을 잰다).
- **결정 2 — 판으로 쌓는다**: 1행 덮어쓰기는 교체가 유실을 다시 만든다. 실제 문서 관리 서비스의 버전 기록과
  같다. `size`·`sha256`은 DB 생성 컬럼. `text_version`의 뜻과 한계(재추출 버전은 판과 연결되지 않는다).
- **결정 3 — 교체·재추출은 텍스트의 새 버전을 만든다**: ADR-017 낙관적 잠금 계약 그대로. 같은 바이트·같은
  추출 결과는 no-op(그 이유: `UPDATE OF content_hash` 트리거).
- **결정 4 — 내려받기는 항상 `attachment`+`nosniff`**, 열람 범위는 문서와 같다(ADR-018·027).
- **트레이드오프**: DB 크기가 원본만큼 커진다(백업·복제·VACUUM 비용). 판 보관 정책(개수·기간)은 없다 —
  ROADMAP으로. 이 기능 이전 업로드 문서는 원본이 없다(교체로 첫 판을 등록할 수 있다). 업로드 상한 50MB가
  실 OpenSQL에서 OpenProxy 경유 `statement_timeout` 30s 안에 들어가는지는 **머지 뒤 VM 실측으로 확인한다** —
  측정 전에 "확인됨"으로 쓰지 마라.
- **대체 관계**: ADR-017 트레이드오프의 "별도 결정"이 이것이다. ADR-033(ZIP 브라우저 해제)은 결정이 유지되지만
  그 이유 중 "원본 비보관에서 따라온다"는 더 이상 근거가 아니다 — 남는 근거(zip bomb·경로 탈출을 서버가
  떠안지 않는다)로 성립한다.

ADR-017 트레이드오프 문단과 ADR-033 「이유」 문단 **끝에** "→ ADR-046(2026-09-23)으로 원본을 보관하게
되었다" 류의 이동 주석만 단다. 원문은 지우지 않는다.

### 2) `docs/PRD.md`

- §4 「원본 비보관은 제품 원칙이다」 문단을 원본 보관으로 개정한다. 유지되는 것: **파일 보관소(ECM)가
  목표는 아니다**, 편집·버전 관리의 대상은 문서 텍스트다. 바뀌는 것: 원본은 재추출의 근거로 판째 보관되고
  내려받을 수 있다.
- §5 C1에 원본 보관·교체·재추출 한 줄. 「하지 않는 것」의 "파일 보관소가 아니다" 설명에서 "§4의 원본 비보관
  원칙"을 새 문장에 맞춘다(보존·기록관리·규정준수 기능은 여전히 하지 않는다).

### 3) `docs/UI_GUIDE.md`

- 101행 부근: 검색 결과 링크는 여전히 문서 상세로 간다 — 이유를 "원본을 보관하지 않기 때문"에서
  "검색·편집·버전의 단위가 문서 텍스트이기 때문"으로 바꾼다.
- 용어 규칙 표: **원본 파일**(업로드한 파일 그 자체, 판으로 쌓인다) · **판**(원본 파일의 버전 — 텍스트
  버전과 다른 말이다)을 더한다. 문서 상세의 「원본 파일」 절(step 6)을 화면 설명에 추가.

### 4) `docs/ARCHITECTURE.md`

「DB 스키마」에 `document_files`(018 실물), migrations 목록 주석, API 표에 `GET /file`·`GET /files/{n}`·
`PUT /file`·`POST /reextract`, 상세 응답의 `files`. 업로드 흐름에 "원본은 같은 트랜잭션에 저장".

### 5) `docs/OPERATIONS.md`

- 업로드 상한 `MAX_UPLOAD_MB`(기본 50) — 이 값이 원본 저장량의 상한이기도 하다.
- 원본이 차지하는 크기 확인 쿼리(`pg_total_relation_size('document_files')`)와 백업에 원본이 포함된다는 점.
- `openarchive reextract <id> | --all` 절: 파서를 고친 뒤 쓴다, 바뀐 문서마다 재임베딩·관계 재계산이
  뒤따른다, 실패 문서 처리.

### 6) `docs/ROADMAP.md` · `/README.md`

- ROADMAP: 판 보관 정책(개수·기간 제한, 이전 판 정리)을 후속 확장점으로 한 줄.
- README 39행·133행 부근의 "원본 파일은 보관하지 않고 추출 텍스트만 남음" 류 문장을 사실대로 고치고,
  사용 방법에 원본 내려받기·교체·다시 추출을 짧게 더한다.

> 두 번째 줄은 비보관을 **현재 사실로 단정하는** 문장이 남았는지 본다. `ADR.md`는 과거 결정의 원문을
> 보존하므로 검사 대상에서 뺐다. 이 grep을 통과하려고 문장을 쪼개거나 표현을 비틀지 마라 — 목적은 사실과
> 어긋난 문장을 고치는 것이다.

## 금지사항

- **과거 ADR 본문을 지우거나 고쳐 쓰지 마라.** 이유: 결정의 이력이 이 문서의 가치다. 이동 주석만 단다.
- **코드를 고치지 마라.** 이유: 이 step은 문서 step이다. 문서와 코드가 어긋나면 코드가 아니라 사실을 적고
  요약에 어긋남을 보고하라.
- **"원본 파일"을 "원문"으로 줄여 쓰지 마라.** 이유: UI_GUIDE 용어 규칙.
- 기존 테스트를 깨뜨리지 마라.
