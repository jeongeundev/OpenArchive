# Step 2: adr-mcp-write

## 배경 — 결정을 기록하고, 예약된 빈칸 하나를 실측치로 채운다

앞의 두 step이 코드를 끝냈다. step 0은 코어가 `visibility` 계약을 스스로 지키게 했고, step 1은
MCP 쓰기 도구 `create_document`를 추가했다. 이 step은 **코드를 한 줄도 고치지 않는다.**
문서만 고친다.

이 step에는 다른 문서 작업과 구별되는 것이 하나 있다. `docs/PRD.md` §4에 **빈칸이 예약되어
있다**:

> 텍스트 공급 API는 코어의 입력 어휘를 바로잡는 초기 변경을 포함했으므로, **판별 기준 3의
> 코어 변경 0줄은 아직 실측하지 않았다.** 다음 공급 인터페이스가 이 진입점을 코어 변경 없이
> 재사용할 때 그 기준을 검증한다.

`docs/ADR.md` ADR-035 결정 1도 같은 약속을 적어 두었다. **step 1이 그 실측을 수행했다.**
이 step은 그 수치를 문서에 옮긴다. 수치를 지어내지 마라 —
`phases/m11d-mcp-write/index.json`의 step 1 `summary`에 적힌 값이 정본이고, 필요하면
직접 재측정하라(아래 작업 1번).

## ✅ 이미 닫힌 결정 — 다시 판단하지 말고 아래대로 진행하라

### 결정 1 — ADR 번호는 **036**이다

`docs/ADR.md`에서 032 다음이 034이며 **033은 비어 있다.** 033은 다른 작업(ZIP 업로드)에
예약되어 있으니 쓰지 마라. 새 ADR은 035 바로 뒤, 파일 끝에 붙인다.

### 결정 2 — ADR-025는 폐기하지 않고 개정한다

ADR-025의 핵심 결정("주체는 `MCP_USER_ID`, 툴 인자로 받지 않는다")은 **폐기되는 것이 아니라
쓰기로 확장되면서 강화된다.** 상태 줄에 개정 이력을 추가하고, "읽기 전용"을 전제한 서술만
현재 상태에 맞춘다. 원 결정문과 그 이유를 지우지 마라.

### 결정 3 — 실측 결과를 유리하게 반올림하지 않는다

step 1의 코어 변경이 0줄이었다면 그대로 적는다. **0줄이 아니었다면 그 수치와 무엇이 왜
바뀌었는지를 적는다.** 판별 기준 3은 통과해야 하는 시험이 아니라 측정하는 척도다.

step 0이 코어를 고쳤다는 사실도 함께 적는다. 그것은 인터페이스 추가 비용이 아니라 **기존 코어
계약의 비대칭을 메운 별건**이며, 그래서 step을 분리했다. 이 구분을 흐리면 실측이 유리하게
보이도록 조작한 것이 된다.

### 결정 4 — CLAUDE.md는 이 step에서 고치지 않는다

프로젝트 규칙에 추가할 만한 항목이 보이더라도 이번엔 넣지 않는다. ADR이 정본이며, 규칙 문서로
승격할지는 사용자가 판단한다.

## 작업

### 1) 실측치를 확인한다

step 1의 `summary`에 적힌 값을 쓰되, 직접 재측정해 대조하라. 이 phase의 코드 커밋 범위에서
코어가 얼마나 바뀌었는지 본다:

```bash
git log --oneline origin/main..HEAD          # 이 phase의 커밋 확인
git diff --stat origin/main..HEAD -- backend/app/ backend/migrations/
git diff --stat origin/main..HEAD -- backend/mcp_server/ backend/tests/
```

첫 번째 diff는 **step 0의 코어 보강**을, 두 번째는 **step 1의 인터페이스 추가**를 보여준다.
두 수치를 구분해서 기록한다.

### 2) `docs/ADR.md`에 **ADR-036**을 추가한다

파일 끝(ADR-035 뒤)에 기존 형식(`### ADR-036: 제목` / `**상태**:` / `**결정 N —**` /
`**이유**` / `**트레이드오프**`)으로 쓴다. 담을 것:

- **주체와 귀속** — `MCP_USER_ID`가 곧 `owner_id`다. 미설정이면 쓰기를 거부한다. 그 이유:
  trusted local context(ADR-025)의 권한은 public **읽기**까지이며, 주체 없는 공급은
  PRD §6 R5(삽입 시점에 owner·visibility 확정)를 만족할 수 없다
- **인자 경계** — 도구 인자는 문서 속성뿐이다. 주체·visibility 위장을 받지 않는다 (R4).
  ADR-028이 REST에서 `X-User-Id`를 제거한 것과 같은 결정임을 밝혀라
- **텍스트 의미론은 ADR-035와 공유한다** — 형식은 `txt`·`md`, 원본 파일 없음(`filename IS NULL`),
  문서 텍스트/추출 텍스트 구분. 같은 질문을 두 번 결정하지 않는다
- **`visibility` 기본값은 `public`으로 REST와 같다** — 같은 서비스 함수의 기본값을 인터페이스마다
  다르게 두면 "하나의 계약 위에서 공급한다"는 C4의 전제가 깨진다. 대신 도구 설명문이 기본값을
  명시한다
- **최소형은 create 하나다** — update/delete 도구, 원격 transport, 파일(pdf/docx) 공급은
  이번 범위 밖이며 각각의 이유를 적어라
- **코어가 `visibility` 계약을 스스로 지킨다** (step 0) — 가드를 `_insert_document` 한 곳에 둔
  이유, REST 라우터를 고치지 않은 이유(pydantic이 먼저 막아 도달 불가), 그리고 **DB CHECK 제약을
  이번에 넣지 않은 판단과 그 남은 위험**을 트레이드오프에 명시하라
- **판별 기준 3의 실측 결과** — 작업 1번의 수치. 이 ADR의 핵심 기록이다

트레이드오프에 반드시 남길 것: stdio 단일 사용자 한계(ADR-025 그대로), MCP 클라이언트가 도구
호출을 승인하는 신뢰 모델에 공급 권한이 얹혔다는 사실, DB 계층 제약 부재.

### 3) `docs/ADR.md`의 ADR-025를 개정한다

- 상태 줄에 개정 이력을 추가한다 (기존 ADR들의 표기 방식을 따라라 — 예: ADR-027의
  `**상태**: 2026-08-09 신규 (#35) · 2026-08-14 경계 위치 개정 (#63)`)
- "읽기 전용 3개 도구"를 전제한 서술을 현재 상태(읽기 3 + 쓰기 1)에 맞춘다
- 미설정 시의 권한 경계가 **읽기와 쓰기에서 다르다**는 것을 명시한다 (public 읽기는 허용,
  쓰기는 거부)
- ADR-036을 가리키는 참조를 남긴다

### 4) `docs/ADR.md`의 ADR-035에 후속 표기를 더한다

ADR-035 결정 1이 예약한 실측이 수행됐음을 적는다. 파일에 이미 있는 `**2026-08-15 후속**:`
절과 같은 방식으로 덧붙이고, **원래 문단은 지우지 마라** — 그 약속이 있었다는 사실이 실측의
맥락이다.

### 5) `docs/PRD.md`를 갱신한다

- **§4 판별 기준 3의 빈칸을 실측치로 교체한다.** "아직 실측하지 않았다"는 서술이 더는 사실이
  아니다. 결정 3에 따라 step 0과 step 1의 수치를 구분해 적어라
- **공급자 쪽 N을 갱신한다** — 파일 업로드·JSON 텍스트에 MCP가 더해졌다. C4가 요구한 세 주체
  (사람·프로그램·AI 에이전트)가 모두 구현됐음을 사실대로 적어라
- **MCP 근거 게이트웨이 절**(:191)이 소비만 서술하고 있다. 공급 도구를 더한다. 단
  **"답변 생성은 플랫폼이 하지 않는다"는 문단은 그대로 둔다** (ADR-015)
- §6 R5·IA-3에 MCP 경로가 포함됨을 확인하고, 누락이면 보완한다

### 6) `docs/ROADMAP.md`를 갱신한다

- MCP·이벤트 절(:77)의 "MCP 쓰기 도구 (2차 후보)"가 구현됐다. 2차 후보에서 내리고 현재
  상태로 옮긴다. **남은 2차 후보(update/delete·원격 transport·웹훅)는 그대로 둔다**
- 확장점 표(:31)의 "커넥터·MCP 쓰기는 다음 확장"을 갱신한다
- 발전 경로 표(:95)의 "남은 결정: 첫 커넥터 선정 · MCP 쓰기 도구 포함 여부" 중 후자가
  해소됐다. **커넥터 쪽은 그대로 둔다**

### 7) `docs/ARCHITECTURE.md`와 `README.md`를 현재 구현과 맞춘다

- `ARCHITECTURE.md` :72 디렉토리 주석의 도구 나열, :85 MCP 서버 설명에 쓰기 도구와
  `MCP_USER_ID` 미설정 시 쓰기 거부를 더한다
- `README.md` :73·:89의 인터페이스 서술 — MCP가 소비 전용이 아님을 반영한다.
  :202의 `MCP_USER_ID` 설명에 **미설정 시 쓰기가 거부된다**는 것을 더한다
- 과대 진술을 만들지 마라. "항상 최신"·"실시간 동기화"는 금지어이며, 보장 범위는
  **버전 일관성 + 최신 수렴**이다 (ADR-015, CLAUDE.md)

## 금지사항

- **코드를 고치지 마라.** 이유: 문서가 구현과 어긋나 보이면 그것은 문서가 틀린 것이거나 앞
  step의 결함이다. 후자라면 여기서 조용히 고치지 말고 `blocked`로 중단하고 사유를 적어라 —
  코드 변경이 `docs(adr)` 커밋에 섞이면 리뷰에서 보이지 않는다.
- **ADR-033 번호를 쓰지 마라.** 이유: 다른 작업(ZIP 업로드)에 예약되어 있다.
- **기존 ADR의 결정문·이유·트레이드오프를 지우지 마라.** 이유: ADR은 append 이력이다.
  바뀐 것은 상태 줄과 후속 절로 표현한다. 특히 규칙 문서(`CLAUDE.md`·`docs/`)의 금지어
  **원문을 지워서 검사를 통과시키는 일**이 이 프로젝트에서 실제로 있었다. 원문은 보존 대상이다.
- **실측치를 반올림하거나 유리하게 서술하지 마라.** 이유: 결정 3. 판별 기준 3은 통과 여부가
  아니라 측정값이다.
- **새 기능·새 확장 후보를 ROADMAP에 추가하지 마라.** 이유: 이 step은 구현된 것을 기록할
  뿐이다. 새 제안의 채택 여부는 사용자가 판단한다.
- **`CLAUDE.md`를 고치지 마라.** 이유: 결정 4.
- **기존 테스트를 깨뜨리지 마라.**
