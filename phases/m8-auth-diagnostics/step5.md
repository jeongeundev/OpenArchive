# Step 5: adr-auth

## 배경 — 비범위였던 것이 범위가 됐다

`docs/PRD.md`의 MVP 제외 사항 첫 줄이 이것이다.

> 실제 인증/인가 시스템 — `X-User-Id` 헤더 기반 데모 사용자 + `visibility`/`owner_id`
> SQL 필터로 "권한이 벡터 검색과 결합됨"만 시연

**이 결정은 "공개 URL로 배포한다"는 전제 없이 내려졌다.** #36이 앱을 EC2에 올려 공개 URL을
관통하면서 전제가 바뀌었고, #37이 최소 로그인을 넣기로 정했다.

**지우지 않고 좁힌다.** 우리가 만든 것은 여전히 최소형이고, *"오픈소스 발전 가능성"*은
**부족한 걸 부족하다고 쓰고 확장 경로를 남기는 것**으로 답한다.

## 읽어야 할 파일

- `docs/PRD.md` — MVP 제외 사항 절. **첫 줄이 수정 대상**이다
- `docs/ADR.md` — ADR-027(권한 원칙) · ADR-029(관계 그래프). 028이 그 사이에 들어간다.
  **ADR-026·027 다음, 029 앞**이 번호 순서다
- `README.md` — 환경변수 절. 세션 수명·쿠키 설정이 늘었다
- `backend/app/services/auth.py` · `backend/app/api/deps.py` — 실제로 만들어진 것.
  **ADR이 코드와 어긋나면 안 된다**

## 작업

### 1) ADR-028을 신설한다

제목: **`### ADR-028: 최소 로그인 — 한 설치 = 한 조직`**
**상태**: `2026-08-1X 신규 (#37)`

**(a) 맥락 — 무엇이 문제였나**

위협은 **`X-User-Id` 위조만이 아니었다.** 기본값이 `public`이고 익명이 읽을 수 있다는 것이며,
그건 **위조조차 필요 없다.**

**(b) 경계 — 로그인이 무엇의 경계인가**

**한 설치 = 한 조직.** `public` = 이 설치의 로그인 사용자 전체, `private` = 나만,
**익명은 아무것도 못 본다.**

- 혼자 쓰는 설치에서는 두 값이 같아져 **모드 분기 없이 개인 지식 관리소**가 된다 —
  이 권한 모델이 **설치 규모에 중립적**이기 때문이다
- ⚠️ **"온프레미스라서"라는 근거를 쓰지 마라.** #37이 세웠다가 **철회했다** —
  인프라에서 제품 형태를 유도하는 비약이다

**(c) 기각 — DB 안 워크스페이스**

근거는 **둘뿐**이다. 다른 이유를 덧붙이지 마라.

1. **요구사항에 테넌시가 한 번도 없다** — 권한은 *정형 데이터 예시*이고, 요구는
   "권한 컬럼이 벡터와 한 SQL에서 결합"까지이며 **술어 4곳이 이미 충족**한다
2. **`workspace_id`는 매우 선택적 필터**라 `MAX_K * 배수 < EF_SEARCH` 계산이 전제하지 않은
   **recall 손실**을 만든다

> ⚠️ **티맥스의 판매 그림에 대한 추측을 근거로 쓰지 마라.** #37이 명시적으로 배제했다.

**(d) 형태 — 왜 이 조합인가**

| 선택 | 근거 |
|---|---|
| `hashlib.scrypt` · `secrets` | **새 의존성 0** — SBOM이 안 바뀐다 |
| 서버 측 세션 | **로그아웃이 진짜로 된다** |
| httponly 쿠키 | localStorage는 **XSS 한 방**. Next.js rewrite로 same-origin이라 CORS 불필요 |
| `X-User-Id` 제거 | 남기면 `curl -H` 한 줄로 통과해 **로그인이 장식**이 된다 |
| 계정은 관리자 발급 | 실무 ECM 패턴. **초대 코드는 SaaS 협업툴 패턴**이라 철회했다 |
| 관리자 = 계정 관리 전용 | 열람 권한을 주면 **ADR-027과 정면 충돌**. 한정하면 열람 술어 **변경 0** |

**(e) 영향 범위 — 걱정보다 훨씬 작았다**

- **MCP 0줄** — 서비스를 직접 import하고 HTTP를 안 탄다
- **열람 술어·관계 그래프 변경 없음**
- 프론트는 `userHeaders()` 하나, 테스트는 `conftest.py` 헬퍼 + 15군데

**(f) 업로드 제한**

파일 10MB · 텍스트 500KB. **실측이 아니라 시연 데이터 최대 문서 90KB의 5배 이상**이라는
근거이며, 상수로 박는다.

**(g) 남은 한계와 확장 경로 — 여기가 "발전 가능성"의 자리다**

실무 문서관리의 권한은 **공간·폴더 단위 + 그룹 기반 + 역할 구분 + 상속/예외**인데
우리는 문서 단위 두 값이다. **요구사항은 충족하므로 결함이 아니다.**

- 부족한 것을 **부족하다고 쓴다**
- 확장 경로(LDAP·디렉터리 연동, 그룹 권한, 공간 단위)를 남긴다
- **`Secure` 쿠키가 HTTPS를 전제한다**는 것도 여기 적는다 — 상시 배포의 선행 작업이다

### 2) `docs/PRD.md`를 정정한다

MVP 제외 사항의 첫 줄을 **지우지 말고 좁힌다.**

- 무엇이 들어왔는지(세션 로그인·관리자 발급 계정)
- 무엇이 여전히 밖인지(그룹·공간·상속·디렉터리 연동)
- **"실무 ECM 기준 최소형"임을 명시**한다

### 3) `README.md` 환경변수

세션 수명 · 쿠키 `Secure` 분기 · 초기 관리자 계정을 어떻게 만드는지 적는다.
**초기 관리자가 없으면 아무도 로그인할 수 없다** — 이 절차가 빠지면 배포가 막힌다.

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 아키텍처 체크리스트를 확인한다:
   - **ADR이 실제 구현과 일치하는가?** step 1~4가 만든 것과 다르면 ADR이 거짓말이다
   - **기각 근거가 둘뿐인가?** 철회된 근거(온프레미스)나 배제한 추측(티맥스)이 섞이면
     #37의 판단이 왜곡된다
   - **ADR-027과 모순되지 않는가?** 관리자는 남의 `private`을 못 본다
   - **한계를 "할 수 있지만 안 했다"로 쓰지 않았는가?** 부족한 것은 부족하다고 쓴다
   - **초기 관리자 생성 절차가 실제로 동작하는가?** 직접 해보라 — 빠지면 배포가 막힌다
3. 결과에 따라 `phases/m8-auth-diagnostics/index.json`의 step 5를 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- **`PRD.md`의 비범위 줄을 삭제하지 마라.** 이유: 좁히는 것이다. 지우면 "원래 그럴 계획이었다"가
  되어 결정의 이력이 사라진다
- **"온프레미스라서"를 근거로 쓰지 마라.** 이유: #37이 세웠다가 철회했다
- **티맥스의 판매 그림 추측을 근거로 쓰지 마라.** 이유: #37이 배제했다
- **관리자에게 열람 권한이 있는 것처럼 쓰지 마라.** 이유: ADR-027과 충돌하고 코드와도 다르다
- **코드를 고치지 마라.** 이유: 이 step은 기록이다
- **"엔터프라이즈급 인증" 같은 과장을 쓰지 마라.** 이유: 최소형이고, 그걸 정직하게 쓰는 것이
  이 ADR의 태도다
