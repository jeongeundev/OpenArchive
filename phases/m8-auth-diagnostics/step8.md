# Step 8: admin-zombie-display

## 배경 — 서술은 m6가 고쳤고, 화면이 남았다

#32가 확인한 것: **좀비 회수의 "자기참조 결함" 서술은 틀렸다.**

- `sweep_zombies`는 **워커 신원으로 거르지 않는 전역 스윕**이다
- **루프 머리에 있어 재기동 즉시 회수한다**(`worker.py:371`)
- 그래서 `pg_cron` 기각은 유지된다

**실질 피해는 `/admin/status`의 거짓 표시뿐**이고, m6가 문서 서술을 정정했으며
**화면 수정이 m8로 배정됐다.**

이 step은 작다. **작다고 대충 하지 마라** — 상태 화면이 거짓말을 하면 복구 데모(m6)의
신뢰도까지 함께 떨어진다.

## 읽어야 할 파일

- `backend/app/worker.py` `sweep_zombies` — **실제 동작.** 화면은 이것을 반영해야 한다
- `backend/app/api/` 상태 라우터 — `/admin/status`가 무엇을 세는지
- `frontend/src/app/admin/` — 지금 화면이 무엇을 어떻게 보여주는지
- `docs/ARCHITECTURE.md` · `docs/ADR.md` — m6가 정정한 서술. **화면이 그것과 어긋나면 안 된다**
- `backend/tests/test_system_api.py` — 상태 API 테스트

## 작업

### 1) 무엇이 거짓인지 먼저 확정한다

**코드를 읽고 화면을 띄워 비교한다.** 추측으로 고치지 마라.

확인할 것:

- `processing`으로 오래 남은 잡을 화면이 **어떻게 부르는가** — "멈춤"·"실패"로 부르면
  거짓이다. 실제로는 **곧 회수될 잡**이다
- 좀비 임계(`zombie_timeout_minutes`)를 화면이 아는가 — 모르면 "오래된"의 기준이 없다
- **워커가 죽었는지 화면이 알 수 있는가** — 알 수 없다면 그렇게 표시해야 한다.
  "정상"으로 보이면 그것도 거짓이다

### 2) 표시를 실제 동작에 맞춘다

- `processing` 잡을 **문제로 표시하지 마라.** 처리 중이거나 회수 대기 중이다
- 임계를 넘은 잡이 있으면 **"회수 대기"**로 표시하고, 회수 주체가 **워커의 다음 폴링**임을
  적는다 — `pg_cron`이 아니다
- **워커 생존 여부를 단정하지 마라.** 상태 화면은 DB만 보므로 워커가 살아 있는지 모른다.
  "최근 처리 시각"처럼 **관측 가능한 사실**로 대신한다

### 3) 문구 규칙

- **"무중단"·"항상 최신"·"실시간"을 쓰지 마라** (ADR-015·020)
- m6가 정한 표현과 **글자 단위로 어긋나지 않게** 한다 — 복구 데모 문구와 상태 화면이
  다른 말을 하면 둘 다 못 믿게 된다

### 4) 테스트

- 임계를 넘은 `processing` 잡이 **"회수 대기"로 분류**되는가
- 임계 이내의 `processing` 잡은 **정상으로 분류**되는가
- 워커 생존을 단정하는 필드가 없는가
- 화면이 실제 카운트를 그대로 보여주는가

#   워커를 띄우면 회수되어 사라지는지 확인한다

## 검증 절차

1. 위 AC 커맨드를 실행하고 **실제로 좀비 상태를 만들어 화면을 확인한다.**
   코드만 읽고 넘기지 마라 — 이 step의 대상이 화면의 거짓말이다.
2. 아키텍처 체크리스트를 확인한다:
   - **`processing` 잡이 문제로 표시되지 않는가?**
   - **회수 주체가 워커의 폴링으로 적혔는가?** `pg_cron`은 기각됐다
   - **워커 생존을 단정하지 않는가?** 상태 화면은 DB만 본다
   - **m6가 정정한 문서 서술과 화면이 같은 말을 하는가?**
   - **`sweep_zombies` 코드를 고치지 않았는가?** 동작은 이미 옳다. 화면만 틀렸다
3. 결과에 따라 `phases/m8-auth-diagnostics/index.json`의 step 8을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- **`sweep_zombies`를 고치지 마라.** 이유: 동작은 이미 옳다 — 전역 스윕이고 루프 머리에서
  재기동 즉시 회수한다. 틀린 것은 화면이다 (#32)
- **`pg_cron`을 도입하지 마라.** 이유: #29·#32가 기각을 유지했다. 화면에 안 보이는
  내부 개선이고, 실질 피해는 표시뿐이었다
- **워커 생존을 추측해 표시하지 마라.** 이유: 상태 화면은 DB만 본다. 모르는 것을
  "정상"으로 쓰면 그게 새로운 거짓이다
- **"무중단"·"실시간"을 쓰지 마라.** 이유: ADR-015·020
- **이 기회에 상태 화면을 재설계하지 마라.** 이유: 외과적 변경 (`CLAUDE.md`).
  거짓 표시 하나를 고치는 step이다
